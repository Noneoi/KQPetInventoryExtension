# 手动公共数据更新

整个工作台（包括战斗回放）使用同一个共享公共数据集，由设置中的更新入口统一维护。下文的“精灵、技能、回放等类别”和多个资料文件，指这个数据集的分块、输出格式或读取视图，不是独立数据源；不得以这些文件划分重新提出多套数据建设。

当前实现（2026-10-14）：`KQPetData/public/current.json` 是公共资料的唯一当前入口；它选择 `public/releases/<清单散列>/manifest.json`，清单引用 `public/objects/<内容散列>/data` 中的七类资料及附件。第一次迁移复用旧 `catalog/` 与实际内置基线并保留原文件。更新器只准备隔离的完整候选，原生发布器核验对象、依赖及报告后一次切换指针，Core 再一次发布完整快照；候选通过、磁盘提交、当前会话应用分别记账。已实现整版恢复，不逐类覆盖现用文件。

设置 → 数据更新的主要入口是“检查并更新”，分类入口位于“高级更新”，并提供重试、查看变化、结果详情、载入已保存资料、恢复上一份资料和导出诊断。精灵、技能、Buff、养成与商店通过各页的资料链接进入共用详情窗口，支持返回/前进；来源与原始记录分层折叠。只展示既有官方字段和明确关系，详情固定入口所用快照，旧回放不借用新全局资料或把静态定义当成本场触发。

已有官方消费规则、来源证明与验收结论应持续复用。`notChecked` 等覆盖字段只表示某个自动检查器没有检查这一项，不表示项目尚未证实它。新增自动检查应引用既有依据；重新研究仅限官方相关定义或代码变化、证据矛盾及实际缺陷影响到的部分。接手约束与成果入口见 [AI 工程交接](AI工程交接文档.md)。

官方来源、解析器与消费者的逐项审计见 [官方数据接入与使用总表（2026-10-14）](官方数据接入与使用总表.md)，其中旧入口和历史状态按该次审计时点阅读；当前版本存储、事务和界面实现以 [第二轮实施记录](共享资料第二轮实施记录.md)、[第三轮实施记录](共享资料第三轮实施记录.md) 及其绑定验收记录为准。下文带日期的数量、耗时与验收路径保留当时事实，不改写为当前安装结论。

## 工作台与战斗回放的完整资源并集

“检查并更新”在解析任何类别前，先合并工作台固定依赖、回放完整官方依据、内置和本地资料已记录的引用。当前固定范围为 81 个 Flash SWF、2 个属性 FUI、17 个 H5 文件及 1 个额外版本依赖；活动子模块、面板和实际图标引用通过官方配置继续发现，不把初始清单当成动态资源上限。历史引用保留原版本和证据状态，不声称都在本次重新下载；精灵图片继续按现有索引按需取图。

同一次检查只有一份 Flash 和 H5 版本快照。Flash 读取 `start.v` 指定的版本包，再应用 `start.u.f`；不使用 `lv` 代替实际加载版本，也不沿用上次检查的版本缓存。H5 校验已核实的加载器，再按版本表、`start.files` 和 `.mix` 优先规则定位文件。相同官方 URL 共用校验过的下载，相同 SWF 字节和类名共用静态导出结果。下载或解析失败按已登记依赖整组保旧，不把局部失败写成全量完成。

解析前先下载、校验所选类别的固定依赖并集；本次资源 SHA 与已保存来源不同，即使官方版本号未变也会重新解析。版本字符串保留官方值，内容校验另存。Flash 引导加载器按 `start.v` 取文件，回放消费者的模块加载器按版本表取文件；两者版本不同就分别保留，各自失败只影响依赖它的类别。H5 技能更新要求原有 21 张输入齐备，并对完整输出表、精灵关联和动画做结构及缩减检查。

共享数据集为工作台和回放提供所需的完整读取视图；同名但不同结构的 `skills`、`buffs` 等输出保留明确契约，不能互相覆盖，也不因此形成独立维护的数据源。工作台字典合并升级到 schema 5，只有增量时间戳严格新于基础表才覆盖；合法空增量保留基础表。源兽 `E4PV2_EInfos`、传说石 `LgsConfig`、潜能指定内嵌 XML 已接入公共更新，补齐过去仅内置的三张表。H5 技能更新读取全部 7 个配置压缩包和 3 张直接表，保存解包文件清单，并用来源字节与解析器指纹决定是否重建。

`KQPetData/public/transactions/<事务>/diagnostics/public-resource-manifest.json` 保存本次并集计划、实际下载和复用、官方版本、SHA、消费者与各类别结果；“已声明”“历史引用”和“本次下载”不混为一谈。原路径 `catalog/public-resource-manifest.json` 只用于隔离工作区中的生成过程或旧版留存，不是现用公共版本入口。临时完整官方包供解析器共用，更新结束清理，必要核验证据按事务保存；不要求用户安装原研究素材目录。完整回放包与精简字典尚未做字段级去重，内容相同的完整对象跨版本复用；公共更新不修改账号详情或个人商店选择。

## 解析范围与更新质量检查（2026-10-13）

这一轮实现覆盖审计和逐项更新检查，不把“下载了资源”写成“所有字段已经理解”。回放输入审计按稳定的来源角色和相对路径记录文件、字节散列、XML 表、H5 字段与已审核的 AS 数据表，区分解析器明确读取、原样保留但未消费、未知字段、历史资料和本次资源核验。独立运行本地审计只证明手头资料的情况，不能证明官网当天的新鲜度，也不能证明解析器已经执行成功。同一实际文件兼任多个输入角色时只统计一次并保留角色别名；不同文件不会因内容相同被合并。本地生成的来源证明字段单列，不能当作官方字段已被理解，未知相邻字段仍须核对。

精灵、技能、回放三个类别在写入前比较当前候选与现用资料；同条数换掉编号、原有字段消失、结构类型改变、数组缩短、已有名称或说明被清空、确定原名退化等都进入审核。回放的技能/Buff 关系重新核对原始明确端点和双向索引，不信任缓存中的“已关联”标记，也不把不同命名空间的相同数字连接起来。精灵字典原始编号与十种技能槽要求准确整数，新增字典列必须先适配，不能被旧的列投影静默丢弃。

2026-10-14 补齐输出差异检查：精灵资料从 12 表扩为 15 表，新增源兽升星计划、升阶计划和有序组合职业条件；回放从 31 个输出路径扩为 88 个，新增客户端展示配置、技能/Buff 反向索引、术语索引、养成链接、召唤/携带等索引和资源规则。来源包装、统计计数和审计报告不冒充游戏数据表。纳入差异比较只表示能发现变化，不表示已经独立证明每个派生索引的含义。

工作台技能更新增加独立官方原文核对：重新读取本次验证过的 13 个 H5 原始表，对精灵原始列与十种技能槽、技能名称/说明/直接动画数据、Buff 展示字段、词条、组合关联、变身定义和保留的英雄/通灵/灵初/神运/天觉规则逐值比较。版本和字节未变时也重新解包核对，不能拿本地缓存的来源标签给自己作证。互换两个合法技能编号下的说明会被拒绝；官方原文与输出同步变更可以通过。该检查器没有覆盖的宠物关联字段列在报告 `sourceFidelity.coverage.notChecked`；它既不证明这些字段已由本检查器校验，也不否定项目其他已保存的官方证据与既有结论。需要补自动检查时先复用已有依据，不重新将整个关联类别宣布为“未证实”。

本次还按已核实的官方消费代码修正三种旧投影：寰力量/异形族按精灵专用技能号准确查表，天觉技能按精灵编号准确查表，机制标签按逗号分隔后的完整标签判断。取消尾号匹配、同组自动继承和子串匹配。清理旧错误说明的许可只适用于这三个字段的具体精灵路径，附原始表位置和散列，并绑定候选整体、旧值、新值和字段存在性；其他字段丢失及结构错误仍拒绝。依据及官方下载链接见 `qa/source-fidelity-20261014/skill-consumer-mapping-evidence.json`。

回放资料另有独立原文核对，按审核过的官方消费优先级检查 7 组核心输出：技能、Buff、属性、技能执行、Buff 执行、组合配置和技能结束特效的核心字段；读取实际 Flash XML、技能文字 AS 字面量表及明确标源的 H5 补充。消费脚本散列单独固定，不信任候选声称的关联成功。资料覆盖审计、输出差异、原文核对各有职责；这仍不是全部派生机制或服务端计算验证。

英雄技的可见皮肤/形态兼容集合也独立从原始配置与已确认消费者重算。2026-10-14 的实际官方更新把一款皮肤的 `show` 改为 `false`，按官方 `getRaceIds/isShow` 规则必须从兼容集合移除，不能为了保留旧条数继续显示。此类数组缩短只有在原始英雄技字段、输入资料与消费代码均通过检查、当前集合完整吻合且收据绑定精确路径和旧新值时才核准；不会放宽其他数组缩短或结构错误。排查证据保存在 `qa/source-fidelity-20261014`。

每次回放更新在覆盖前运行内置 QtCore 检查器，使用与工作台相同的战报解析、状态和过程模型。三份经脱敏校验的完整真实战报固定核对 336 次行动、3093 个过程快照，包含多目标、数值顺序、显示恢复及分身登场；黄金期望来自此前已验收的旧基线，候选不能改写。报告同时绑定实际候选文件、解包后 JSON、夹具集合和检查器散列。工具缺失、超时、返回失败、漏案例、报告错配均拒绝更新；未变化分支同样执行。正常原生核对约 8 秒，只在手动更新期间运行。它不覆盖 GUI 动画、未在三份样本出现的召唤执行分支或全部未来机制，范围详见 `assets/battle-replay-regression/README.txt`。技能名称与说明的变更由原文核对负责，不能用旧文字冻结正常官方更新。

官方原本为空的说明、已有的未确定身份或引用缺口保留原样。新增引用缺口需核对；技能字典的槽、皮肤与形态如果能从本次完整原表证明“原文确实引用且目标定义确实缺席”，报告保留逐项原文位置和散列，记为官方资料缺项。此证据不能豁免字段丢失、非法类型、错连和反向索引错误。工作台精简字典和回放完整定义有不同用途，不要求条数相等。

当前正式更新将质量报告保存在 `KQPetData/public/transactions/<事务>/quality/<类别>.json`，包含候选内容散列、表与字段清单、差异、引用检查、独立原文核对、回放输入覆盖及真实战报回归结果；旧 `data-tools/quality/<类别>-latest-attempt.json` 是隔离工作区的中间输出或历史文件。同一事务的 `validation.json` 绑定整版检查及报告散列，`changes.json` 保存变化，`receipt.json` 区分检查、候选通过、磁盘提交和会话应用。通过检查仍须经过原生完整试读、并发指针核对和一次提交；不能以部分成功冒充全量完成。普通界面显示可读结果，技术编号、字段路径和证据留在展开详情与报告中。

皮肤模块新增准确的消费范围校验：原名解析实际使用的五个类必须与已核验版本逐字节相同；配置只允许 `SKIN_DEFINES_SRC` 和 `SKIN_GROUPS_SRC` 两个已核实字面量数组的数据改变，数组外文本必须完全相同，未知字段、类型或编号格式拒绝。2026-10-13 对比还发现分享页与互动海报两个 UI 类变化，它们没有用于此原名解析；不能把这次结论写成“整个 SWF 只有数据变化”。官方链接、包与脚本散列、新旧差异存于 `qa/skin-review`。

回放当前消费者代码的字节校验与数据脚本骨架校验保持有效。经实际骨架校验的纯数据变动保存旧新脚本散列收据；首次在新导出文件中发现的表，只有能证明其生产包与已审核历史包完全相同时，才按既有覆盖缺口记账，不能凭“以前没看到”认定官网新增。未知消费者变化、新增未识别字段和已消费字段消失仍须适配后再发布。星神、徽章、星轮等资料的来源审核不等于验证服务端公式。

没有把所有未知字段自动变成已解析，也没有开放未审核的消费者变动。继续补解析器时，以覆盖报告中的具体表、字段、官方消费代码和真实战报为依据。第二轮已完成完整候选、原生整版提交及恢复；各类别仍有各自质量检查，但不再分别覆盖现用公共文件。以下保留解析质量阶段的历史验收路径：`build-v2/validation/parser-quality-20261013`、`build-v2/validation/parser-fidelity-20261014` 及最终绑定构建报告 `build-v2/validation/parser-fidelity-final-verified-20261014`。

## 兑换商店的自动添加与手动补充

“设置 → 数据更新 → 高级更新 → 兑换商店”更新时，同时扫描兑换、签到、进度及其他奖励，候选只保留指定精灵提升。精灵自选、材料任选和自选礼包排除；旧扫描结果即使曾被勾选，也不会重新显示。明确的“指定养成或普通材料二选一”保留养成内容并标注二选一条件，需要手动勾选，包括通行证的完美天赋和源兽神觉提升。默认培养兑换初始勾选，可以取消；更新和重启后保留取消结果。点击“手动补充商店 / 兑换项目”可搜索相关扫描结果、展开商店，勾选或取消整店、单项和搜索结果；“保存选择”成功后立即更新商店显示。静态费用、进度门槛和次数限制可以直接查看，账号已用及剩余次数在商店中手动刷新。

候选列表和商店界面都隐藏未开放、已到期的项目，空商店也不显示。有效期按北京时间判断；官方给出具体时刻时保留时刻并在到期后自动更新界面，明确的活动总截止时间不能被条目日期延长。未注明截止时间不代表永久开放。 截止时间还会沿官方福利总览的时间范围和实际页签绑定关联到子活动，并读取主界面实际引用的“活动时间”标签。页签范围遵循官方凌晨 2 点关闭语义，总览按其代码包含最后一天；只有月日的面板标签要求官方发布日能唯一确定年份，不使用本机当前年份补猜。任务期限、首周折扣、未使用的图片和复用同一页签的多期奖励不会套作整个活动的截止日。奖励模块不变而总览、页签或面板资源更新时，也会重新计算有效期。整店操作选中的是当时可见的项目，后续新增的手动项目默认不选。选择按活动来源、商店、条目和奖励身份隔离；名称或价格更新继续保留，同一编号更换奖励则需重新选择。选择文件独立保存在 `catalog/shop-selection.json`，公共更新不会覆盖；保存失败保持上一份已保存的显示结果。

按用户要求移除神幻诺雅挑战、永恒战场全民挑战奖励、大乔神运进化和灵初神暗帝释天全民得。排除规则匹配活动来源，覆盖新扫描和旧缓存；常驻“永恒战场商店”是独立来源，继续保留。

解析器版本升级时，即使官方资源版本号相同，也会重建旧扫描结果。支持静态培养表、官方构造器包装、多奖励分支和按玩家档位筛选的奖励。识别 `Choice`／`SelectPrizes`、分离选项表和 139 类自选礼包以排除普通自选项目；只对两分支中一项为明确正向精灵范围和具体强化效果、另一项为普通材料的结构保留手动养成候选，排除范围不明、多层自选和礼包分支。礼包定义变更会使依赖它的扫描结果重算。普通固定材料、随机礼包和纯活动宣传页面不列入候选。扫描范围仍为当前 HUD、近期发布及其显式引用，不代表覆盖全部历史商店。

活动结构解析还支持 `rewardType/rewardParams/filter` 强化与任选、并列字段的关卡进度奖励、VIP 奖励元组、官方强化接口直接消费的字段、通行证实际档位关联的选项表，以及活动明确指定精灵的公共养成套餐。索引、静态复制函数和构造器只解析可验证的常量，不执行游戏代码。公共养成服务与接口定义独立跟踪版本，变化后重新识别依赖的活动。入口引用按队列遍历并去重，避免多层入口漏扫和循环引用。

抽奖池中的非自选养成奖励标记为“抽奖奖励”，不会按免费领取处理。排除式或运行时精灵范围可以保留真实的手动养成项目，但不生成“所有精灵适用”的规则；公共套餐动态费用仍以游戏面板为准。通行证只关联当前奖励档位实际引用的内容，精灵／材料自选项目不显示，明确的指定养成与材料二选一则显示具体养成效果和条件。明确的开放时间晚于发布目录时，以活动开放时间为准。仅写“通用养成”“指定养成”的条目按官方强化类型改为具体效果；没有明细的极品套餐补充实际组成。修正名称不会改变奖励身份及已有手动勾选。

手动补充窗口下方会显示“活动尚未完整解析 · 查看原因”。同一活动已识别的奖励继续可用，未知类型、动态参数或缺少公共奖励定义的部分单独列出原因；完全不同的新结构仍需要适配。活动解析状态区分完整识别、部分识别、待解析及没有相关奖励，合并目录保存 `activityPending`，下次打开仍可查看。

只有设置中的“检查并更新”和“高级更新”中的分类按钮会启动联网检查。启动插件、切页、筛选和排序不启动更新器。更新器退出后没有后台轮询或常驻辅助进程。

不再为没有奖励表的页面生成“活动入口（奖励项目待解析）”。概览页的图标渲染引用不能证明存在领取项目，应沿其官方跳转寻找实际活动。真实的动态奖励结构如果尚未支持，原因保存在活动目录的 `pending` 和公共更新结果中；已确认的旧项目可保留但标记过期。不同玩家档位和通行证奖励分支单独列出，未确认适用档位时不混用账号次数或价格。奖励能列出与培养适用性能够自动判断是两件事：例如指定某种星神的奖励可以显示，但尚未支持的适用判断仍标注待确认。

资产页点击“重新计算养成分析”后，优先读取本地；在线时缺少的实例详情会自动补读一次，失败保留未知。养成诊断支持四类养成、时代和原名评级的组合筛选，汇总与搜索结果一致；皮肤沿官方 `groupRaceId` 关系找原型，关系缺失或成环时不猜评级。源兽／精华／元魂为培养剩余总消耗，未扣账号材料库存，红星已按每只精灵的装备和本宠背包扣除。

公共更新包含七个组件：精灵与养成资料、精灵技能资料、指定精灵兑换、精灵图片索引、星神/属性图标、日常任务/活动、战斗回放资料。全部引用保存在同一版本清单，未变化的对象复用；分类检查通过 `--components` 选择，再按已登记依赖扩展。精灵、技能、商店、回放、图片和图标一起检查，核心失败时整组保旧；图片失败可沿用旧对象，不阻止已通过的核心资料应用；日常独立处理。最终仍一次提交完整清单。“候选通过”不等于“全部检查完成”，部分失败或保旧不能报成全量成功。图片请求固定资料快照中的索引，精灵图按来源身份隔离并核对 PNG 摘要，公共图标存于 `images/public-icons/<PNG散列>.png`，旧快照不读取同名新图。

精灵资料同时更新基础/增量字典、星神规则、元魂费用、源兽计划、星轮节点、物品与货币名称。属性、职业及组合职业名称读取官方枚举，不再维护固定名称表。源兽材料名称由普通材料定义和 `E4PV2_EInfos` 联合补全。

源兽星级/阶级上限在详情、商店、资产和缺口页共用同一份动态计划；派生算法版本为 10，星轮突破仅适用于灵初精灵，旧算法派生索引需要重建。原始详情与图片继续保留。计划未知时保留已知数字，不能判已满培养。

商店解析官方 `CommonEnhancePrize` 的明确种族列表。日常任务、活动入口和红点关系来自当前 `dailytaskservice`、`config/config`、`library/gameconst`。新增同结构条目按官方配置更新；未知新培养类型、未支持活动结构和缺失官方字段会写入 本次事务的 `diagnostics/public-update-status.json` 并明确提示，不把部分成功报成全量成功。账号材料和个人任务次数仍使用原有手动查询入口。

指定精灵兑换更新还会从当前官方活动注册表、HUD、近期发布记录及显式活动链接发现独立活动目录，并应用紧急配置和官方临时下线配置。`@sb` 种族范围按官方进化链、初始多形态和皮肤还原规则展开；进化依赖更新时，已有活动的适用精灵也重新计算。2026-09-13 的独立公开资源验证覆盖本次发现的 **8 个活动兑换目录、72 个项目**；这是当前发现范围的快照，历史活动全集及未支持的新结构仍需按更新结果中的覆盖记录判断。发现路径、规则和限制见 [限时活动指定精灵兑换目录](activity-exchange-public-data.md)。

独立活动保留各自 `sourceKey`，不与主商店共享编号或兑换次数。本次发现的 72 项都有静态限次额度，69 项费用固定，3 项具有明确动态价格档位。在商店手动点击“刷新兑换次数”，会读取其中 7 个目录、68 项的账号次数和活动币余额，并通过公共 `MaterialExtension / 3_11 / {}` 查询标准货币及道具；价格仅在所需账号条件明确时选档。圣冕秘阁 4 项已显示静态费用和总限 1 次，所需宿主 `ci` 参数尚未接入，当前次数仍未读取。详细来源和边界见 [活动兑换次数与资源观察](activity-exchange-observations.md)。

这些只读观察写入当前账号的 `activity-exchanges.json`，按活动来源和查询范围隔离；V 币、回归币等专属币不混入其他活动或公共材料余额。界面区分“只读观察”与“上次”数据，读取成功不会自动授予限次周期有效性。失败保留对应来源上次有效数值与时间。目录更新仅处理公共资料，启动、切页和后台都不自动查询活动账号数据；当前覆盖数量不构成全部活动保证。

精灵分析中的“刷新材料背包”用于手动更新养成材料，一次点击并行查询 `MaterialExtension / 3_11 / {}` 和 `PJXExtension / 2_32_0 / null`。前者读取元魂、精华道具，后者读取空闲源兽仓库 `eps` 堆叠数量；源兽各等级按同一 `sourceId` 合计，不混入精灵已装备的源兽。明确空列表更新为 0，缺字段、坏包和超时保留该组旧数量与观察时间。账号文件 `cultivation-materials.json` 使用 schema 2，并记录源兽来源 `2_32_0.eps-warehouse`；旧 schema 1 道具继续恢复，旧通用 `24` 观察等待一次手动源兽仓库查询。协议证据见 [源兽材料背包读取](source-beast-inventory-protocol.md)。

资产中的“统计本地红星”独立扫描当前账号本地精灵详情，包含已装备和本宠星神背包，普通红星、万变红星分别计数。该入口不联网、不写缓存，也不触发全账号养成分析；只统计已有本地记录，并显示缺失或跳过情况。

星神与属性图标按当前请求固定索引中的文件路径和 PNG 摘要读取；手动更新将变化内容保存为不可变图标对象，新 ID 无需改代码。旧快照引用保留；缺图或校验不符使用占位或已核验内置图，不借用同编号的新图。

## 精灵图片

索引按种族/外观 ID 建立，完全不依赖名称。当前官方 `PetIconContainer` 使用 `peticon/peticon{face}` 和 `mmo.pet.peticon{face}_L`。`VersManager` 对未列出的 SWF 使用官方默认版本 `2000`，因此版本表没有单列的新精灵也能找到资源。高位外观 ID 通常取 `% 10000`；当次 `pet/petdataservice` 中 `PetIconConfig.AVAILABLE_FACEID_AFTER10000` 提供保留原 ID 的例外列表，更新器动态提取该列表。

图片索引契约：`schemaVersion: 1`，`images` 可按 `race_face` 指定条目，`faces` 按外观 ID 提供 `{swfUrl, symbol, revision}`；`faceIdExceptions` 保存当次官方例外。正式缓存按来源身份隔离到 `images/pets/sources/<来源身份>/race_face.png` 并保存来源元数据及 PNG 摘要；旧扁平图片仅在证据吻合时复用。

缺图时可使用已准备的本地工具下载这一个官方 SWF，定位 SymbolClass 对应的精确精灵 sprite，导出第一帧透明 PNG，不运行 ActionScript。已有有效本地图直接复用。只有用户手动检查更新时，才根据来源/版本替换已有图；失败保留原图，下次手动检查可重试。缺图操作不会自行下载工具依赖；工具尚未准备时提示先检查数据更新。

2026-09-13 定向验证使用独立临时数据根：9639 个外观索引；`[灵初]轮转·命运之轮` 的官方 `peticon7529~2000.swf`（1,916,039 字节，SHA-256 `248f0a3b04e542b36c293ab38a6e3a37af207a61d2c7a8e11595a5df115e042e`）精确导出 `_L` 图片（448,559 字节）。这只是公开资源验证，没有访问账号接口或真实客户端。
