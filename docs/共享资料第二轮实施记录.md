本轮的实现、验收与安装分别记录。最终交付事实统一看 `build-v2/validation/shared-data-round2-20261014/validation.json`；不存在或未通过时，不能据此文档声称已经安装、提交资料或在当前会话应用。第三轮的设置页整体改版与公共资料详情导航另行实施。

## 完整版本和原始资料

公共资料对象存于 `public/objects/<内容散列>/data`，版本清单存于 `public/releases/<清单散列>/manifest.json`。七类资料都有独立对象引用及实际来源，商店的活动兑换、进化适用附件也纳入版本。不同版本共用内容相同的对象；检查时间、下载进度和本次结果单独存入事务记录。

`public/current.json` 是唯一的公共资料当前入口。它包含当前和上一版本，并用独立的提交标识与原指针字节散列防止并发覆盖及切换后又回到同一版本的冲突。它与程序的 `KQPetRuntime/active.json` 各自管理资料和程序。

第一次迁移按现用文件及实际内置基线准备完整视图，原 `catalog` 保留。旧精灵覆盖文件与基线合成时，合成前的原始字节也保存为不可变对象并明确引用。沿用已有的旧官方缓存日期保护，日期判断提取到共用函数，避免迁移重新引入已修正的旧名称。来源没有登记的历史文件仍标为历史来源未登记；确实缺失的资料明确不可用，不补造官方记录。

迁移来源的外层登记与原资料内部证据是两层信息。例如旧压缩回放包的外层登记保留文件散列与时间，包内原有官方来源、消费依据和已确认解释全部原样保留；外层未提升来源摘要不代表这些结论变成未知。后续正式官方更新的来源及质量报告按同一版本完整登记。

## 候选 检查 提交 应用

设置更新使用同次构建的完整更新工具集，按明确依赖扩大必要检查范围。Python 只在事务工作区调用原有分类解析器，现用 `catalog` 不再作为正常更新写入目标。低层解析器必须显式声明隔离工作区，正式命令行也走候选与同一原生发布器。

候选记录绑定原公共版本、实际清单、全部对象和独立质量报告。原生发布器核对对象的真实字节、报告与对象的关联、已有消费者可读性，提交前再次核对当前指针。只有这些步骤成功才原子切换公共入口。原文审计实际读取的必要文件按内容保存并与报告绑定，不拿候选自己的来源描述充当原文证明。

正常主程序在原有 Storage I/O 工作线程准备和提交，GUI 不读大文件。Core 收到完整快照后，在同一次回调中替换整套读取视图，再通知观察者；最后记录当前会话已应用。

更新收据分别保留：

| 状态 | 证明的事情 |
|---|---|
| 已检查 | 本次实际执行的范围、输入与结果 |
| 候选通过 | 完整候选及其关联检查通过，尚不表示生效 |
| 磁盘已提交 | 公共当前入口已指向该版本 |
| 当前会话已应用 | 本进程已经发布对应的完整快照 |

指针切换前中断继续使用原版本。切换后退出或记录失败，启动时按指针中的事务标识恢复；不能把已经保存的新版本说成没有提交，也不能把只生成候选说成当前会话已更新。

命令行原生入口为 `KQPublicDatasetCheck`，迁移、提交和恢复复用程序里的同一存储库。首次没有公共入口时先检查并建立现用旧资料基线；之后的准备模式只生成更新候选。命令行提交仅表示磁盘状态，不冒称有一个图形会话已经应用。

## 依赖和保旧范围

精灵、技能、商店与回放之间已有共享原表和明确读取关系，核心依赖组必须保持一致；日常按其独立官方模块检查。图片与图标使用精灵定义，但图片失败不会反向阻塞已经通过的核心资料。共享定义失败与单个活动原有待适配项分别记录，后者不被包装成一次新的公共定义故障。

同一官方地址和版本的实际字节仍需检查。解析缓存绑定原包内容、解析代码以及实际解包工具身份，解析器变化使相关缓存失效。必要的独立原文与真实战报校验继续执行；没有完整消费者依赖依据的地方继续保留原严格保护。

字节没有改变但本次确已通过新解析器检查的分块，保留原对象和来源，并登记实际通过的解析器身份。这种身份变化可以形成一次新清单，后续同身份检查不重复强制重建；失败或整组保旧的分块不能据此获得新的验证身份。

候选工作区正常收尾清理，必要原文和审计记录已保存后才移除解包临时文件。不为每次更新复制整个精灵图片缓存。

## 运行时一致性

详情、技能、商店适用性、日常摘要与分析从完整快照取得输入，计算途中不重新查询可能已经换版的单例。结果发布检查实际依赖身份；资料更新期间完成的旧计算不能作为新资料的结果。仅图片改变时，未受影响的详情和分析继续复用。

已打开的战报保留原快照。新的“使用更新后的资料”操作先用原战报在新资料上重新解释，成功后按原记录位置、行动者和回合等稳定信息唯一定位，回到该行动的开始。新旧内部帧索引不通用；定位或解析失败保留原视图及其播放设置。

图片请求固定索引对象、官方来源和实际 PNG 身份。原索引仍可用于后续补图，不能因为当前指针变化而借用新图。图标改为按内容定位，已有快照使用的图片与版本对象不在运行期间冒险回收。

## 恢复 兼容与缓存管理

设置中增加“恢复上一份资料”，走同样的完整试读与原子提交，再整套发布给当前会话。旧战报仍保持其原资料，是否重新解释由用户选择。

原程序和公共目录的兼容恢复需要成对记录实际版本及文件散列；迁移保留原目录，不能把旧程序回退说成一定使用当前新资料格式。安装验证记录应明确演练范围、当前指针与旧目录的保留情况。

当前采用保守保留：有效版本、旧快照与事务可能引用的对象不删除。跨进程引用未可靠登记前，只列出可进一步检查的对象，不执行运行期公共对象回收。缓存清理、备份和迁移也必须理解公共版本引用，不能清掉内容图标或遗漏当前版本链。

备份保存公共清单、对象、事务和保留的原文证据；备份前后核对当前指针，排除未完成工作区及锁。恢复时先在隔离目录核对所有内容、版本引用和路径，再导入公共不可变文件，通过原生 `--restore-version` 完整试读并提交，不直接复制备份里的当前指针。公共提交失败时不先恢复账号文件；提交成功后即使账号文件恢复失败，也保留明确的磁盘提交结果，并让 Core 重新载入及确认公共版本。旧备份没有公共版本时，当前公共资料保留并明确说明。

“恢复上一份资料”只恢复公共资料，个人商店选择仍从原独立记录套用。完整缓存备份恢复保留原有账号恢复及重启要求，不把磁盘上的账号恢复说成当前账号会话已经重新读取。

## 验收与边界

本轮检查包括对象与报告篡改、完整范围、依赖组保旧、原文保留、取消、提交前后故障、并发冲突、旧快照、回滚、旧目录兼容及缓存管理。各项定向结果与最终整包结果分别记录，前者不能替代最终程序和配套更新器的验收。

`public_dataset_store_smoke` 使用隔离的结构夹具检查存储和 Core 发布，不据此制造任何游戏机制结论。真实官方候选检查和既有 21 份战报另外执行，均绑定实际工具、资料及输入散列。最终程序、启动器和更新器资源必须来自同一通过整包测试的构建。

回放重建沿用“检查原 JSON → 无损打包”的既有流程；未变化检查也可能直接读取压缩包。发布检查同时核对实际压缩对象和它展开后的逐字节 JSON，要求回归记录指向其中实际受检的文件，并且解包内容散列一致，不把两种文件的散列混为一谈。

继续保留的边界：普通有效精灵图片缓存不会主动探测每个同地址同版本的静默图片改包；已知的商店适用性及活动配置待适配项仍需如实显示；此轮没有改变账号事实、服务端计算或既定回放排除范围。没有实际执行的游戏登录和客户端操作不写成已经通过。
