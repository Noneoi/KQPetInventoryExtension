# 共享资料第三轮实施记录

本轮把设置中的更新结果、各页面的官方资料详情和既有版本系统接通。整个工作台继续共用现有 `KQPetData`，使用第二轮的完整候选、原生发布器和不可变快照。官方定义、战报原始记录及已确认规则保持原有职责。

最终构建、完整测试、实测性能、界面检查及日常客户端安装身份统一记录在 `build-v2/validation/shared-data-round3-20261014/validation.json`。该收据尚未生成或其检查未通过时，不能将源码实现说成已经安装完成。第二轮最终安装记录仍作为本轮基线保留。

## 更新入口与持久结果

设置的主要入口为“检查并更新”。七类资料的分类按钮收进“高级更新”，同时说明选中项需要检查的依赖范围。精灵、技能、商店与回放按已有依赖一起检查；图片问题不阻止已经通过检查的核心资料应用；日常使用独立模块。

更新结果由 `PublicUpdateService` 在 Storage Auxiliary 线程读取公共收据和清单，GUI 只显示值对象。再次打开设置恢复最近请求、结果与当前窗口实际加载的版本。旧进程留下的 `sessionApplied` 不能证明新进程已加载，实际状态由当前 Core 的完整快照提供。

普通界面区分内容未变化、已应用、部分完成、失败保旧、取消、候选待应用、磁盘已提交待载入和已恢复。已检查候选仍走原生完整校验和指针冲突保护；载入已提交资料只读取当前公共入口。恢复仅切换公共定义，不改账号数据和个人商店选择。

准备工具、获取资源、解析、检查和应用使用结构化阶段事件。有实际计数才显示完成数与总数，其余阶段使用不定进度。提交前可取消；进入完整应用后等待提交结果。请求在工具准备前已有独立事务身份，因此准备失败与取消也有记录。收据的创建时间固定，后续会话确认不能让旧检查挤掉较新的失败或取消。

队列拒绝、资料尚未就绪等没有新事务的情况使用独立操作提示，保留上一次正式结果。缓存任务忙和图片任务忙不冒充已经开始更新，也不会把更新按钮永久锁住。

## 变化说明与诊断

候选检查报告绑定变化摘要的实际字节、事务及候选版本。摘要按用户对象显示名称、增加或修订或移除，以及旧新说明；官方空说明保持为空。技术编号和原字段进入进一步展开的详情。较早记录没有逐项变化文件时，明确显示未记录，不能当成零变化。

变化摘要有显示数量上限，完整公共原记录仍保存在对应不可变对象中，不因摘要截断而丢弃。诊断导出只收集公共资料清单、公共事务与相关检查摘要，隐藏本地绝对路径；不遍历账号目录、不打包战报。导出在后台原子写入用户选定的文件。

## 共用官方资料详情

新增 `PublicDataDetailQuery` 纯查询和 `PublicDataDetailDialog` 共用窗口。精灵名称、技能与词条、回放中的精灵和效果、已装备养成定义、商店项目均可从已有入口查看官方记录与明确关联。

查询以视图、表名和记录键共同确定身份。H5 技能与 Flash 战斗技能保持不同空间，同号不借用说明；元魂、星轮、星神、潜能、源兽、传说石与神源兽装备的入口保存原解析已经取得的定义键，不按展示名反查。商店材料缺名称时说明名称未收录，不把编号当用户名称。

每个入口保留它当时使用的完整资料快照。回放入口只接受本场已经固定的回放包，不能到全局最新技能表借文字。关联表示静态配置中存在明确引用，不生成本场触发、施加来源、层数或装备事实。

详情窗口可以返回和前进，每个历史页保持自己版本、滚动位置及来源展开状态。查看详情不会重新解析当前战报或重置其动作、时间线与 Buff 折叠。来源先显示已有官方资源链接，技术键、解析依据和完整原记录再深入展开；旧回放包中已有的 `provenance` 也保留在来源里。

## 测量与优化范围

本轮先保存未优化的存储实现及测量程序，再用相同的已安装官方资料，在隔离目录比较当前版本读取、首次回放、重复查询、恢复、无变化候选、局部变更、整版发布及持有旧回放时的发布。每次使用独立子进程，分别记录墙钟时间、进程 CPU、峰值内存、逻辑 I/O 和独立 Qt 事件循环心跳。

测量不清空系统文件缓存，逻辑 I/O 不能当物理磁盘流量；心跳只证明测量程序主循环的响应，不冒称真实游戏界面的帧率。适配器基线固定存储实现与实际数据、可执行文件身份，并非把新测量接口说成旧安装程序自带功能。网络下载和官方解包验收另外记录，不用网络波动计算本地优化收益。

已实现的优化针对候选语义检查中一次无用的完整 JSON 对象构建。原本构建后立刻丢弃的对象改为直接使用经过文件散列检查和无损解包的字节，继续交给原语义校验路径。保留对象根、深度、节点数、字符预算和真实输入散列检查；另补非法尾逗号、重复键、Unicode 排序及压缩包边界回归。提交时仍重新读取实际对象，不使用跨提交缓存来跳过完整性核对。

2026 年 10 月 14 日同输入交错配对中，本地全无变化候选复验的中位时间从 15.487 秒降至 12.760 秒，进程峰值从 760.2 MiB 降至 506.6 MiB。未改动的当前资料读取控制项为 0.642 秒和 0.650 秒。Python 在单次读取中复用已经严格核对的 JSON 解析结果，同一真实压缩对象的读取函数由 9.480 秒降至 3.624 秒，峰值内存基本不变；两项均不能直接当作联网更新全程提速。

完整矩阵及环境差异见 [原生实测报告](../build-v2/validation/shared-data-round3-20261014/performance-results.md) 和 [Python 对象读取测量](../build-v2/validation/shared-data-round3-20261014/performance-python-payload.json)。首次回放仍需完整解码，旧新回放同时保留时约 1.3 GiB 的进程峰值仍存在。

当前定义、保留历史、图片、解析工具、来源证据、临时文件与账号分别盘点。没有新增数据库，也不为界面详情常驻另一套回放 JSON。有效版本和旧快照可能引用的对象继续保留，在没有可靠跨进程引用登记前不实施自动回收。

实际客户端验收还发现缓存统计的兼容错误：官方技能资料中的 `psychicsSkills` 含合法空键，Windows PowerShell 5 的 `ConvertFrom-Json` 在将它投影为属性时失败。缓存工具改用系统已有的字典解析检查普通资料对象；指针、清单和图标索引继续使用原字段校验与图片保护。空键及大小写不同键原样保留，不清洗官方记录。坏 JSON、非对象根及原有跨版本图片保护已有回归，现用目录的只读统计验证通过。修复只涉及缓存工具，不要求重新下载、解包或更新公共资料；实际程序激活状态和内置脚本字节见本轮验证目录中的 `cache-empty-key-fix/validation.json`。
