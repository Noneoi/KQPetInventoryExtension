- 各切片在同一工作目录协作，文件所有权明确；共享 CMake 由主线集成。保留原先未提交改动。
- 各接口切片按阶段集成，保持文件所有权；当前进入异步数据、工作台和发布的集成验证，未完成项目不以已通过的局部测试代替。

## 原文与派生缓存纵向集成（2026-09-12 晚）

- Application 已接 `PetRecordCache` 与 `PetDerivationCache`。前者保留原始字段并对未保存、未派生记录加保护；后者在既有 Compute 上生成紧凑 facts，键包含账号、epoch、实例、详情内存版本、元数据 revision/摘要及分析版本。原始详情与外借 GUI/Compute 引用各自持有可计费 lease。
- 手动分析先准备当前全部实例的 facts。曾经完整但已淘汰的原文优先使用同版本 facts；需要重建时读取对应磁盘事实。磁盘文件丢失或内容身份不符会结束本轮并保留上次结果，不将已知个体降成 Unknown 后继续。原本缺详情的实例仍参与全部 P 的分析。
- 新增 `analysis_cache_integration_smoke`，使用真实 Repository、Storage、缓存、Controller、Worker 与 Projection。验证本地新文件补齐、maxRecords=1 的逐出、热分析零重算、仅选中原文投影、零裸原文导出、丢失后保留结果、同内容恢复、取消和账号隔离。`build-v2/ctest-cache-fixture-identity.log` 通过，0.27 s；不是性能验收样本。
- 该纵向测试实际发现：成功写入未返回内容摘要，导致 Repository 自称持久化成功而原文缓存保持保护、后续读取无法推进。已在 I/O 的最终提交字节上补 SHA-256，覆盖普通、JSON 与 merge 写入；读取摘要与保存摘要使用同一字节定义。
- Publisher 的库存投影改用轻量摘要与 facts，仅发布精灵页/商店页的最多两个原文关注项；元数据切换时释放旧 facts 映射。Projection 将详情通知分成每次最多 32 条、目标 8 ms 的批次，并加账号切换和同步删除保护。`build-v2/ctest-projection-slices.log` 的 runtime、projection、纵向缓存三项通过，总计 0.78 s。
- 已补“账号总战力是否全部已知”的值字段；缺少个体战力时，界面及历史显示部分未知，不将部分合计或默认零称为已知账号总战力。旧快照缺少该声明时保持未知。
- 此时尚未完成的门槛包括：原文 partial 覆盖回归、可丢弃磁盘派生索引、生产 GUI 对 facts 的完整消费、选中详情后台构建、商品跨轮编译缓存、完整性能矩阵与综合内存测量、UI 构建依赖收窄、最终真实客户端及发行验收。局部测试通过不替代这些门槛；日常部署未覆盖。

## 用户调整预算执行方式（2026-09-12）

- 用户明确要求：“不要这么严格！！！不要严格参考预算限制，可以有余地！！！”。此要求优先于原方案的预算和采样安排。
- 耗时、内存数字改作参考目标，允许合理余量；分析默认结果上限由 64 MiB 调整至 128 MiB，总量由 256 MiB 调整至 512 MiB。保留有界保护和已有可靠优化，不继续为了旧数字扩展复杂优化。
- 后续优先完成共享详情、界面整合与主要流程验证；代表性完整数据能运行、实际体验流畅即可推进。性能报告保留实际值和原参考值，不再将超出旧目标等同于整项重构失败；完整极限矩阵按实际需要运行。
- 完整一万实例的快照可以装入原文件大小上限，但 JSON 保留值和编码临时空间超过旧 32 MiB I/O 队列额度。共享 I/O 额度留出 128 MiB 余量，单文件大小和任务数量约束仍保留，避免将正常大快照拒绝为保存失败。
