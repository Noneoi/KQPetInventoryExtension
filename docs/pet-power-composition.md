# 精灵战斗力组成与至高判定

更新：2026-09-17，派生算法版本 13。服务器分项作观察权威；星神/星轮本地重算；天赋/潜能用官方公式复核。本地计算只读取缓存和已经收到的详情，不发送培养、装备或兑换命令。该时代没有的系统不显示、不计算。

## 五个数分别表示什么

| 名称 | 数据与含义 |
|---|---|
| 官方当前战斗力 | `zdl` 原样观察值，单独保留；不能据此判断有没有缺培养 |
| 官方极限战斗力 | `xzdl` 原样观察值。官方 `PetProgressionStargod.runBattlePowerMax()` 使用同等级金星 51 的战力乘实际槽数；星轮普通极限只合计节点，不含突破后的三选加成 |
| 已装备本地战斗力 | 非星神/星轮的当前分项 + 实际已装星神按实际槽等级计算 + 当前星轮节点计算 |
| 本地持有可达战斗力 | 在上一个公式里，用本精灵已装与 `sgsp` 背包的合法最优星神配置替换已装星神。槽等级保持当前等级，不假设已经升级，也不把其它精灵或公共背包的星神转入 |
| 至高战斗力 | 各适用系统的完整培养目标，加上本精灵实际槽数、官方槽位等级上限和职业限制下的最高星神配置，以及适用星轮的全部节点；仅灵初精灵计算突破后的三选加成 |

“本地持有可达”是一项分析结果，不代表已经修改装备。已有红星没有装备时，可能已经具备至高培养条件，同时仍有“调整装备”的行动。已有资源够用时，不继续建议兑换同一颗红星。

精灵列表“战斗力/极限战斗力”后缀只比较本地 `current` 与 `highest`：两者已知且 `current >= highest` 时显示“（至高）”，低于或未知时不加任何后缀。这里 `current` 按实际槽位等级计算，包含本宠星神背包中可合法使用的星神；官方 `xzdl` 不参与这一后缀判定。

当前完整回包明确提供以下 11 个分项；不适用的分项明确为 0。当前与极限必须都完整、键一致、数值有效，才能给出完整本地总数、至高和满培养结论。双方同时缺字段也不算完整。未知值显示未知，不当 0。

## 分项与计算边界

| 键 | 分项 | 具体构成与来源 |
|---|---|---|
| `lv` | 等级与基础成长 | 官方 `PetProgressionLevel`：等级 × 种族基础战力 ÷ 200，整数截断。**当前/极限仍用回包**；本地不另造 `BasicZhanDouLi` 表 |
| `iv` | 天赋与星能 | 官方 `PetProgressionGifted`：`trunc(等级 × 有效天赋合计 × 3 ÷ 200)`。有效合计按职业攻击类型选轨（旧 8 轨计 7、神职 6 轨计 5）。**展示回包**；有 `ip` 时用该公式复核，不一致只记原因，不改当前值 |
| `pl` | 潜能 | 官方名「潜能」，不是职业熟练度。`trunc(当前等级÷最大等级×40×潜能等级)`。有 `cps` 与字典 `maxLevel` 时复核。极限以回包为准（传说及以后为 0） |
| `sgv` | 星神 | **本地重算**：已装 + 本精灵背包，同类去重、职业限制、实际槽等级最大权匹配。官方极限用金星 51；至高用合法最高配置。调整装备 / 升槽 / 缺星分开 |
| `ep` | 源兽装备 | 回包分项。神运起归零 |
| `gsv` | 守护石（已移除） | 2017-06-09 起官方移除，回包恒 0；仍占 11 键，不当活养成 |
| `lav` | 学习力（已移除） | 同上。未证实的 `lp` 串不参与 |
| `lsv` | 传说石 | 回包分项（传说技档位 + 5 槽） |
| `bsv` | 元魂 | 回包分项；培养需求另拆 `badge` 串看等级/觉醒 |
| `asv` | 天迹星轮 | **本地重算**节点。仅灵初在已点亮且选中 ≥3 时 +150。官方极限不含这 150；至高在灵初计入 |
| `sjv` | 神源兽 | 回包分项 |

**口径分工**：官方 `zdl` / `xzdl` / `czdlv` / `mzdlv` 是观察值。本地当前 = 该时代存在的回包分项 + 本地星神（已有可装）+ 本地星轮（仅星迹及以后）。至高在星神/星轮上可以高于官方极限。天赋/潜能用官方公式复核回包，不替代回包。该时代没有的系统（如神属没有元魂/星轮/神源兽）不显示、不计算、不产生培养缺口。`PetBuild` 把等级+天赋合并截断，本地合计相对 `zdl` 仍可能差 0 或 1，不偷偷凑齐。

如果以后官方增加新分项，保留该原键和数值；只有当前、目标都存在且有效时才纳入合计。元数据缺失或格式改变时保留已知分项，至高保持未知。

## 星神：已装、已有、升级与获得分别计算

1. `sgs` 每一个 `#` 段就是一个实际槽位，不按时代写死格数。空普通槽 `0`、空万变槽 `-2` 都保留；单值及旧式第 4 字段按官方 `PetStarGodSlot.valueOf()` 规则处理。
2. 星神等级属于槽位。背包 `sgsp` 存放定义 ID；放入哪个槽位，就使用该槽位当前等级的战力。
3. 已装普通星神和本精灵背包合并；同一星神定义或同类 `type` 不能重复占据多个普通槽。两个相同红星或红金同类不能冒充两种可装红星。
4. 按官方 `StarGodType` 的职业限制排除不适合或不能提升该精灵战力的普通候选。职业来自精灵种族字典，不能用未确认的 `rt` 回退。
5. 万变槽独立处理。`sgs` 显示 ID 与底座/来源 ID 分开，持有来源万变红星算已具备；万变星神不占普通槽类型配额。
6. 当前配置采用最大权匹配：不同类型匹配实际槽等级，取最优总和；空槽也可以使用已经在本精灵背包的星神。不是“取最强几颗后全部按 8 级计算”。
7. 再将同一批已有星神放到官方最高槽等级计算“已有星神升满后”。最后将全部官方合法星神作为候选，计算至高星神目标。
8. 碎片、星元、经验材料不是可装备星神，不因它们缺少高等级战力表而使整个目标未知；未知的新可装备星神仍需更新定义。

| 比较 | 行动性质 |
|---|---|
| 本地已有配置 − 已装备配置 | 已有星神可调整装备；无需购买 |
| 已有星神升满后 − 当前槽等级下已有配置 | 槽位升级缺口 |
| 至高星神目标 − 已有星神升满后 | 确实还需获得的星神战力 |
| 普通槽数量 − 已有合法不同类红星数量 | 真正缺少的普通红星种类数，最小为 0 |
| 有万变槽但本精灵未持有万变红星 | 独立万变红星需求；已有金色/红色品质分别保存 |

当前官方逐级战力示例（实际计算查定义表，不固定套此行）：

| 品质 / 等级 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 金色，如气吞山河 | 100 | 150 | 200 | 250 | 300 | 350 | 425 | 500 |
| 红色，如气贯星河 | 140 | 210 | 280 | 350 | 420 | 490 | 570 | 650 |

星轮突破仅适用于灵初精灵。先按精确种族官方时代标记判定适用性，再读取 `astrolabebr` 和实际点亮、选中节点；灵初已突破但不足 3 个选中星灵时提示调整星轮。神运、星迹保留节点培养，不显示突破、不加 150。启元及更早没有星轮，详情和分析都不展示也不计算。未知时代不会默认成灵初。

一个已保存详情的匿名实例可说明差别：官方当前 30360，官方极限 29400；非星神部分 25550，已装星神 4810。本精灵背包另有可用红星，因此按已有配置应计 5200 星神战力，本地持有可达 30750，至高也是 30750。此时应建议调整装备，普通红星兑换需求为零。该例仅离线读取本地文件验证，没有改动真实客户端或缓存。

## 刷新配合

算法是纯函数，输入是已冻结的详情与官方字典。详情版本或字典版本变化后复用现有派生任务生成新分析；分析页只消费同一份结果，不独自请求仓库或重复计算。点击精灵、手动刷新详情沿用现有只读刷新机制；离线保留已有详情及结果，手动检查数据更新后按新字典重算。商店和资产也消费同一份星神、分项及缺口事实。

## 官方依据与证据

官方公开资讯确认星轮节点激活、外圈选择与独立养成系统存在；例如[星迹时代开启公告](https://aoqi.100bt.com/xinwen/310971.html)及[灵初精灵养成公告](https://aoqi.100bt.com/xinwen/320711.html)。资讯页面不提供完整数值公式；上述公式依据以下官方客户端公开资源的解包代码，不以攻略文章推导数值。

- 官方资源入口：`https://aoqi.100bt.com/play/` 的 `start.swf`、版本表及其引用的模块。
- `Interfaces/.../PetBuild.as`、`progression/PetProgressionLevel.as`、`PetProgressionGifted.as`、`PetProgressionStargod.as`：分项组合、有效天赋与金星极限基准。
- `Interfaces/.../PetStarGodSlot.as`：实际槽序列、显示 ID、来源 ID 与万变槽编码。
- `stargodservice/.../stargodv3/StarGodService.as::getBattlePower`：逐颗使用显示定义和当前槽等级的 `battlePower`。
- `stargodservice/.../Sgsv3Controller.as::checkEquip`：普通星神类型重复限制、万变槽限制、职业不加战力与职业排斥限制。
- 当前官方 `materialservice~2026091011614836.swf` → `mmo/material/stargod/StarGodItemService.as`，配合当前 `interfaces~2026091011614836.swf` 的 `PetJob`：星神品质、类型、限制职业；生成器同时保留 `limited`。
- 当前官方 `astrolabeservice~2026082767617311.swf`：488 个节点的 `battlePower`、`locatedTypeId`；`Interfaces/.../PetAstrolabe.as::getCurrentBattlePower/getMaxBattlePower` 明确三选 150 与普通节点目标。`locatedTypeId=0/1/2` 分别为核心/连结/外圈。

仓库代码对应 `src/domain/pet_power_calculator.cpp`；定向测试 `tests/pet_power_composition_smoke.cpp` 覆盖未装红星、重复类型、职业限制、实际槽等级、无星轮、三选加成、未知字段与当前官方完整目录。官方定义随着“检查数据更新”刷新到本地，无需为每一只新精灵编写硬编码分支。
