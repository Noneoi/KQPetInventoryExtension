# v3.2.0 改良实施记录

基线：独立从 GitHub 克隆 `v3.2.0`，提交 `3ab79f6a978b28ba846efa261950163713f5f0f7`。
工作分支：`improve/v3.2.0-workbench`。现有工程和客户端保持独立。

工程版本：3.2.1 预览。日期：2026-10-18。

## 已实现

- Flash 使用实际入口 `v` 和覆盖项；H5 核对资源映射、`.mix` 别名、覆盖项及实际内容。同版本内容修订也进入检查，技能单独更新不依赖 Flash。
- 更新脚本随程序内置；Python、Java、JPEXS 首次准备后复用，无需每次编译工程。相同资源共享下载，脚本提取结果校验后跨次复用。
- 修复部分 PowerShell 环境找不到 `Get-FileHash` 导致启动失败的问题，改用 .NET SHA-256 接口。
- 六类候选先经过 Python 检查、文件摘要校验和程序原有解析器验证，再原子切换目录版本。相关内存目录先同时发布，再通知页面；相同内容不再使所有派生缓存失效。
- 唯一任务身份、阶段与耗时、六类结果、检查及应用时间、变化与完整来源诊断；取消、定向重试、完整核验、重新载入和上一版恢复。结构待适配不假装能靠网络重试解决。
- 分开记录磁盘保存与工作台载入。精简进度不覆盖详细诊断；重开设置恢复结果，中断不冒充成功。失败仍保留各类上次应用时间。
- 旧 `catalog/` 目录及本机后续版本 `public/current.json` 的六类资料可导入；清单损坏时不悄悄退回旧目录。
- 商店增加当前开放、全部已发现、未开始、已结束、手动隐藏及待识别活动查看，保留用户勾选规则。开放时间未知时单独说明。
- 详情可补读本轮失败、取消和缺失项；图片可定向重试本轮失败项。日常目录和账号进度时间分别说明，缓存统计区分原始资料、公共目录、图片、派生缓存和工具。
- 相同输入的分析重复点击继续现有任务；容量失败明确说明范围并保留旧完整结果，区分完整详情从内存移出与实际读取失败。

## 实测与验证

在本机隔离目录测量，工具已预置，不包含首次工具下载；联网耗时随网络及官方来源变化。

| 场景 | 总时间 | 游戏资料下载 | Java 提取 |
|---|---:|---:|---:|
| 无提取缓存的首次官方资料检查 | 339.3 秒 | 10.95 MiB | 283.5 秒；基础字典约 153.5 秒 |
| 规则重新解析，提取缓存可复用 | 42.9 秒 | 10.29 MiB | 0 次；94 次提取缓存命中 |
| 官方资料无变化的后续检查 | 4.7 秒 | 7.99 MiB | 0 次 |

另外取两个配置类，各做五组相同输入配对并核对输出 SHA-256。直接提取中位数约 1.326 秒，校验缓存复用约 0.014 秒；这是配置类测量，不代表整个更新流程的固定加速倍数。`parse` 是类别处理阶段总耗时，包含内部下载、解压与提取，不能与子阶段相加。

首次改良实测识别 9,737 个精灵、20,821 条技能、44 组商店，包含竞技场商店。当时把活动提取提示、个体适用条件提示与更新失败混在同一结果中，导致资料已保存和载入仍显示“部分完成”。该表述与状态处理已按下述复核修正，历史测量 JSON 保留原始记录。

## 更新结果与通用活动提取复核

- 设置表格分别显示“更新结果”“变化 / 失败原因”“资料提示”。提示详情用活动名称、商品名称和原因呈现，完整原始数据仍可导出。下载或校验失败仍保留失败状态与重试入口；只有配置识别或适用条件提示时不再标成更新失败。
- 公共养成的奖励内容与精灵范围分开声明时，按 `showStrengthenPanel` 的实际参数关联；静态数组经 `.map()` 转换为 `ActReward` 时，按消费方法、字段投影和明确目标提取，并继续关联已有的价格与限次消费者。
- 通用规则不写活动名、日期、精灵 ID 或奖励值白名单。未来名称与字段重命名、不同目标及奖励、改价后的选择身份、未消费配置、图标展示、跨页目标混用、运行时额外改写均有对应检查。新结构无法确认时保留具体提示，不推测价格、目标或兑换次数。
- 公共验证模板只跳转养成面板时，不再统计为一个缺失商店。明确指向某只精灵但公共配置仍无对应记录的入口继续提示。
- 使用同一批官方资料全目录对比，商店分组由 44 增至 46，商品由 259 增至 264：新增 5 个项目，原项目删除 0 个。新增项目来自此前漏识别的内部页面；其他活动同结构使用相同提取规则。商品变化与商店分组变化分别计数。
- 真实公共资料经过内置脚本、原生校验及内存发布后，`complete`、`diskCommitted`、`sessionApplied` 均为真。完整的 51 条个体适用条件提示与 2 条活动配置提示在提交后仍保留，不被进度消息截断。
- 剩余两条关联提示是首充的公共商城购买配置，以及星迹幻诺的公共养成引用。前者已识别四个养成项目，尚未完整关联购买条件；后者仍需确认共享配置映射。不能据此称两个完整活动未适配。
- `shop_pet_eligibility`、战力计算及养成派生代码与 v3.2.0 标签一致；排位赛“指定精灵装备1颗红星”和“指定精灵满1条星迹”的原有判断保留。

本次针对性验证包括 65 项活动解析用例、23 项更新器用例、10 项版本存储用例、12 项交易事实用例，以及原生更新和设置界面检查。完整发行验证报告绑定最后生成的预览包。证据见 `docs/evidence/public-update-notices-and-activity-20261018.json`。

## 当前客户端安装后核对（2026-10-18）

安装后设置仍展示的“部分培养适用判断待适配；3 条活动兑换配置待识别”，来自该客户端 10 月 14 日保存的旧版更新记录。安装程序并不会伪造新一次数据检查结果。已备份旧记录和版本指针，使用新程序同一数据更新服务在当前公共数据目录执行实际检查。

这次实际检查暴露了隔离目录中没有旧图片时无法覆盖的问题：候选目录复用已安装的 Java/JPEXS，但图片提取仍需要在候选目录内创建临时目录。补齐该目录创建，并验证失败保留旧图、成功原子替换及临时文件清理。

继续实际读取两张图片发现，官方 2892、2947 图片使用 ZWS 压缩，而图片符号读取仅接受 FWS/CWS。复用已有活动解析中采用的有界 LZMA 解压方式，补齐图片符号读取的 ZWS 支持；覆盖三种压缩格式、截断输入、过大字典和长度不符。

同时核对前后商品发现，“装备任选1颗红星”等两项已证明目标与养成效果的商品被名称中的“任选”误过滤。展示过滤改为先核对原始奖励与规范化目标、效果是否一致；真实 Choice、SelectPrizes、自选礼包和不一致的记录继续排除。使用不同名称、效果及目标的通用测试，活动解析缓存版本更新为 20；未修改任何养成适用性算法。

## 52 条养成记录的行为核对

已冻结当前报告的 52 条真实商品配置，并以同一批 1,478 份本地详情调用客户端实际的 `deriveShopPet`、`describeShopPetRule` 与派生缓存序列化流程。49 条有对应实例，形成 1,948 次商品—精灵匹配；另 3 条是灵初钻石昆吾的内圈、外圈、专属星迹，本地没有对应实例，使用缺失、已完成、缺少详情三组明确标注的构造状态验证，不能称作真实账号验证。

官方证据来自已校验内容摘要的 `strengthencomboservice`、`interfaces` 和 `common` 脚本。34 的参数形式走同一个 OneRed 路径；92 为增加阶数而非升至指定阶数。35 指向具体星神，检查本精灵装备和背包中的所有权以及职业、普通槽位限制。81/82/83 分别按官方面板的圈层、专属标记、开放状态和同链前置节点判断；61 使用服务器 `gt` 天赋等级。保留原有 34、84、85、86、89 等 24 类规则的判断结果。

修复前套餐有 9 次匹配可以靠已有分项判断为有用，因此“52 项全部不能判断”不成立。修复后本地回放的 1,948 次匹配都有明确结果。新事实随缓存序列化、内存计量和分析版本 18 一起更新，避免旧派生结果继续使用；数字字符串形式的星神编号也按原数据契约识别。实际剩余次数、余额及在线领取条件仍由现有账号条件层处理。

逐项结果与来源摘要见 `docs/evidence/cultivation-52-audit-20261018.json`。原始详情和反编译中间文件仅在忽略的本机验证目录，不进入源码包。

## 两条活动配置关联修复

按官方实际调用核对两条记录，修复的是数据关联。商城直购分支通过同一个索引选中原奖励，再将独立配置传入 `DirectBuyInfo.forNormal` 和 `buyDirectly`。通用规则把商品编号、标价及数量附到原奖励，保留原编号，不产生重复商品；经公共接口验证这是外部商城支付，不把整数标价或奖励中的充值档位当成钻石扣费。领取上限由奖励类的布尔状态、界面未领取条件及领取后赋值共同确认，账号当前购买、领取状态保持独立。

公共养成 `showPanelCombo` 先归一皮肤与形态。只有单个入口精灵缺少独立目录时，官方才调用 `getPetOrderEvoLink` 选择末端进化；不能用 `@sb` 的多形态后续进化集合替代。已验证公共方法并使用其进化配置，入口 4487 因此关联到 5864 的 14 项套餐；不把这些商品错误应用到 4487，也不读取相邻活动的配置。隐藏测试分组继续排除，含歧义分支、循环或未验证方法的配置继续报出具体原因。

活动解析版本升至 21，进化映射缓存版本升至 2，公共奖励支持缓存版本升至 3；共享面板入口参与进化依赖失效检查。重复检查复用已校验的脚本和解析结果。活动名、配置类名、精灵编号、商城编号及金额均不作为适配分支。

同一官方快照回放 68 个有脚本的模块，其余未发现相关奖励的模块保持现有发现结果；用户已排除的活动继续排除。两条待识别记录均消除，活动商品从 240 项增至 254 项，原 240 项的养成代码、奖励表达式和精灵范围保持一致，无商品删除。改名、改编号、重新定价、未消费的配置、支付对象被修改、冲突购买入口、进化歧义及未确认目标均有自动验证。证据见 `docs/evidence/activity-links-audit-20261018.json`；完整原生更新及安装结果保存在本机验证目录。

## 已确认的边界

万级个体仍可能超过现有派生缓存容量，本轮未实现跨批结果汇总及任意规模增量分析。这属于原方案 D 批的独立容量改造；不会通过提高限制或发布不完整统计假装完成。

当前交付为独立工程和隔离验证用预览包。未发布 GitHub Release，未执行真实账号的全场景人工验收。原始 v3.2.0 标签不改写。公共资料更新不代表账号余额、兑换次数或任务进度也已刷新。
