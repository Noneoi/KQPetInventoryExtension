# 本地缓存与手动更新

详情、公共资料和图片共用一个长期目录。默认是客户端目录下的 `KQPetData`，与每次升级的插件文件夹分开。设置的“本地缓存”页显示实际路径并可直接打开。

## 读取与刷新

| 操作 | 行为 |
| --- | --- |
| 启动、打开页面、排序、筛选、翻页 | 读取已有本地数据，不主动查询仓库详情 |
| 点击一只背包或仓库精灵 | 立即显示已有详情；游戏在线时只查询这一只，返回有效数据后刷新显示并覆盖保存 |
| 刷新背包/仓库 | 更新列表 |
| 刷新仓库详情 | 只处理所勾选时代的精灵；支持暂停、继续、取消 |
| 断网、超时、响应无效 | 保留已有详情和更新时间；没有缓存时显示缺失状态 |
| 检查数据更新 | 联网检查官方精灵字典、指定精灵兑换商店和图片索引，按成功组件更新 |
| 查看已有有效图片 | 只读本地文件 |
| 查看缺失图片 | 允许下载并保存；失败会记住，避免反复自动下载 |
| 补齐缺失图片 | 为当前账号列表中的精灵补图，也重试此前失败的图片；已有图片只读本地 |

程序不定时联网检查公共资料。商店页面的目录更新按钮与设置中的“检查数据更新”使用同一入口。兑换次数属于账号状态，仍由“刷新兑换次数”查询。

首次检查数据更新会准备本地转换工具，用于读取官方 SWF 字典和精灵立绘。工具放在固定的 `data-tools` 子目录，之后复用。首次使用可能需要几分钟；缺少工具时图片状态会提示先检查数据更新。官方字段结构将来发生变化时，更新失败的组件保留旧文件并说明原因。

## 磁盘组织

- `accounts/<账号>/details/<实例ID>.json`：账号的最新有效详情；同一实例覆盖保存。
- `accounts/<账号>/inventory.json`：账号列表；商店、日常缓存也按账号保存。
- `catalog/`：当前公共字典、指定精灵商店和图片索引。
- `images/pets/<种族ID>_<外观ID>.png`：稳定的图片文件；改名、皮肤名称和插件版本不会产生另一份同外观缓存。
- 图片旁的 JSON 保存来源与版本，失败记录用于避免自动重复请求。明确检查更新发现资源变化时，下载成功后覆盖原图，失败保留原图。

旧版本的图片会按种族和外观复用、迁入稳定路径，原文件保留；设置中的“整理旧版重复图片”只删除已有有效稳定缓存替代的旧文件。缓存长期保留，无自动磁盘清理。

只读来源的有效账号观察也能保存，但保存成功不代表已获得游戏写操作权限。

## 管理和迁移

设置提供占用、详情/图片数量、当前账号列表的缺图数和最后更新时间；可删除指定账号、实例、图片或清理缓存类别。删除后已经打开的内容可能暂留内存，再次有效刷新可以重新保存。

可备份到 ZIP，也可恢复 ZIP。恢复默认只补齐缺失文件，覆盖旧文件需要勾选并确认；完整恢复内容在下次启动载入。

更换目录有“复制缓存并切换”和“直接切换”两种选择，均在下次启动生效。复制需要空目标目录：启动器在客户端启动前复制并提交新路径，旧目录保留；失败继续使用旧目录，取消此次迁移，避免每次启动反复失败。

目录配置保存在客户端目录下的 `KQPetDataRoot.json`，优先于启动环境的旧路径设置。升级插件沿用此配置。不要手工将缓存目录设为磁盘根目录或其他程序的工作目录。

本次仅进行构建和缓存、更新器、启动器迁移的定向测试。真实客户端交互由用户手动验证。
