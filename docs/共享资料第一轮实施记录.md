# 共享资料第一轮实施记录

日期：2026 年 10 月 14 日。对应 [改造计划](共享资料与更新系统改造计划.md) 的 A1 至 A4。本轮改动读取与说明规则、日常公共更新入口、奖励筛选和图片身份；同一个 `KQPetData` 继续供整个工作台使用，存储仍兼容 JSON/brpack。

本轮源码修改和定向检查已经展开，最终测试、官方更新及实际安装状态统一记录在 `build-v2/validation/shared-data-round1-20261014/`。其中 `validation.json` 是最终安装核对入口；文件不存在或未标记通过时，不表示本轮已部署。第二轮的整套版本发布与恢复尚未实施。

## 共用读取与原始资料保留

新增 [公共读取契约](../src/contracts/public_data_contract.h) 和 [纯资料视图](../src/domain/public_data_view.h)，按读取视图、表、准确标识定位原记录，区分缺项、已存在、合法空、容器不符和视图不符。查询不转换相似名称，不将技能与 Buff 的同号记录连接起来，不删除未识别原字段。

`PetMetadataView` 的定义查询、专门的技能读取器和回放名称查询已经复用该接口。它负责精确读取和保留原值；各领域原有的官方规则仍由相应消费者解释，不把不同投影强行压成一个表。

[字段去向清单](../qa/shared-data-round1-20261014/field-disposition.json) 连接了七类视图、15 张精灵表、11 张技能表、回放 34 个顶层键、206 个已盘点路径及 20 个导出文件。引用的旧盘点路径是当时的依据快照；新代码入口按本记录定位。公共版本统一发布属于第二轮，本轮不伪造一个全局发布版本号。

## 星轮读取与显示

新增 [星轮记录读取函数](../src/domain/pet_astrolabe_record.cpp)，详情、战力与培养缺口共用。复用已保存的官方 `PetAstrolabeTraceSlot.init` 和 `PetAstrolabeChain`：节点 0 合法，缺少第三段时为未选中。

无效字段与“未点亮却选中”等异常组合保留已收到的原状态，不形成确定的培养结论。星轮专用展示器将异常和未知节点单列为“状态待确认”，显示已知字段及原因，不再把未知节点丢弃或混进正常点亮列表。

公共更新与离线字典生成器统一引用 `PET_DICTIONARY_SCHEMA`，当前为 5，消除两个入口的格式标记差异。

## 技能名称 词条 与默认界面

新增 [共用技能读取器](../src/domain/public_skill_view.h)，技能类型按明确槽位、逗号分隔后的完整标签和官方转化技能类型读取。相似精灵名字、部分标签及技能名不再替代类型。

词条只使用精确当前说明或已核实的官方中点参数格式。罗马后缀、连字符和部分名称不能用于借另一条说明。官方明确空说明保持为空；缺少准确说明时展示当前原文及缺项状态。

正常完整参数沿用官方规则。缺参和多位参数采用完整占位符匹配，未提供值显示“指定数值”，避免把缺失的 `ARG2` 拼成第一个参数后加数字。原说明仍在资料中。

本地关键词简评和历史补充不再默认覆盖当前官方说明。补充生成器重建时保留完整旧快照，并对本地关键词产物明确标注来源和默认隐藏；本轮没有改写原始内置补充文件。技能默认界面移除了种族、技能、进化前及皮肤编号；相关对象通过同目录的准确名字显示，原始 JSON 保留编号。

已有官方类型和词条依据、真实补充重建与定向 UI 验证见 [技能验证记录](../qa/shared-data-phase-a-20261014/skill-a3-verification.json)。

## 商店奖励按结构筛选

Python 解析器及 C++ 商店消费者同时移除仅凭“自选”“任选”或类似文案的排除。`Choice`、`SelectPrizes`、自选礼包身份及多奖励分支等明确结构仍按已核规则处理，四类既定排除活动保持原范围。

已经明确的指定培养与普通材料二选一继续作为人工候选；无法从已支持结构确定的候选不自动提升为默认项目。公共更新不会重置用户选择。

复核发现昆吾特惠中“装备任选红星 3 颗”有明确 `CommonEnhancePrize` 培养结构，曾被 C++ 文案过滤误删。本轮恢复该条目的展示；真实内置活动测试因此由 51 项变为 52 项，对应商店由 3 项变为 4 项。该变化是恢复原官方条目，不是新增编造的奖励。

主商店解析版本改为 5，活动解析版本改为 19，使下次检查按新筛选规则重建旧结果。

## 日常规则与公共写入

日常“刷新”已移除调用旧本地 AS 导入的正常入口，继续读取原有账号进度。公共目录由设置更新服务维护。

新增 [官方日常规则解析器](../tools/public_routine_rules.py) 与 [共用机会规则读取](../src/domain/routine_opportunity_rules.h)，实际解析星轮探险、全民斗技、新农场、竞技场四类官方模块。相关函数签名与函数体按已核契约检查，数值配置允许更新；消费公式、回包字段或映射变化时保留整块旧目录并记录原因。

日常界面和资产机会汇总使用相同规则。旧目录缺少规则时，已经收到的直接次数继续显示并计入已知小计；只有依赖额度的反算部分不能形成确定结果。

| 场景 | 本轮处理 |
|---|---|
| 星轮今日 | 直接显示回包 `ti`；配置中的每日声明不用于反算已用次数 |
| 星轮本周 | 使用实际官方每周配置和已核消费者处理 `wgt` |
| 全民斗技 | 今日按公共基础额度与原购买/使用字段读取；本周已有剩余继续读回包，不拿单独声明替代 |
| 农场 | `pt`、`rft` 为已收到的储存次数；储存上限和每日补充按官方邀请档位区分。缺少邀请信息时只缺上限，不清空直接次数 |
| 竞技场 | 读取实际场地定义及其与回包字段的映射，避免把旁边同为 8 的其他配置当成日额度 |

农场旧界面中的 16 是储存上限，不能叫每日补充额度；当前官方档位可使上限变为 20，每日补充为 4 或 5。数值的具体选档仍依真实回包信息和官方配置，不能根据玩家名字或缺失字段推断。

官方下载链接、原始包及脚本散列保存在 [日常官方输入记录](../qa/routine-rules-20261014/official-inputs.json)，隔离的真实更新验证见 [日常更新验证](../qa/routine-rules-20261014/official-update-verification.json)。这些资料已经取得，后续直接复用。

## 图片定位与旧页面

精灵图片独立更新现在复用现成的官方加载器默认版本读取与检查。新下载使用准确 race/face、官方资源和精确符号，停止通过历史 `candidateNames` 名称映射查找新图片。

图片按来源身份分隔路径，原 PNG 内容摘要继续保留。请求绑定其已读取的来源，旧页面不会因重载索引改读新版同名图片；同来源对象也需要保持内容一致，内容冲突必须拒绝或明确报告，不能覆盖后冒充原图。

有实际来源、符号及内容证明的旧缓存可迁移；裸文件或仅通过名字得到的旧缓存不删除、不猜着重新归类。缺少准确来源的图片使用占位及重试。新程序与相应提取脚本必须一起发布，避免旧程序只认识扁平路径而新脚本只生成新路径。

来源身份只在实际读到或核验到相应内容后建立。已有有效缓存不会因同一 URL 的强制重试而自动证明网站字节未变；本轮不宣称每次检查都下载了全部图片。

## 验证与交付入口

定向检查覆盖：视图与同号隔离、合法空和原字段保留、节点零及两段星轮、异常状态展示、精确词条和缺参、奖励结构筛选、日常旧目录与真实规则更新、图片新旧页面并存及内容冲突。

最终交付继续使用与源码绑定的完整注册测试、内置更新器导出校验和官方资源隔离更新。安装时保留当前程序版本与将替换的公共文件；原版 EXE、稳定入口和账号数据不作为此次改动目标。运行中的客户端按既有流程暂存，只有实际激活后才记为已覆盖。

当前所有发布事实以 `build-v2/validation/shared-data-round1-20261014/validation.json` 为准。该记录应列明完整测试报告、官方更新结果、实际文件散列、备份目录、当前程序状态，以及未执行的真实游戏登录测试范围。
