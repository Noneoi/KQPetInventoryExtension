# 氪奇精灵工作台

给奥奇传说玩家用的养成辅助工具：在 **氪奇 Pro 官方客户端** 里加一个「精灵工作台」窗口，把背包和仓库里的精灵、培养缺口、兑换商店、日常任务和账号资产集中到一处查看，帮你判断下一步该练谁、该换什么。

插件通过外置启动器和进程内扩展工作，**不修改原版客户端 EXE**，卸载后客户端恢复原样。

> **声明**
>
> - 本项目**不盈利**，只是为了方便奥奇玩家养成，与奥奇传说官方、氪奇官方均无隶属关系。
> - 按现状提供，**不保证能用**，也不保证以后的游戏或客户端版本兼容。使用前请自行备份。

## 支持范围

- **目前只支持氪奇 Pro 官方客户端**（已在 V1.1.4 上验证）。其他客户端以后再做——不过用的人应该也不多。
- **脱机版**暂时不做：做起来问题比较多，后面打算用 Astra 和 Fable 再试试。
- 有问题直接提 [Issue](https://github.com/Noneoi/KQPetInventoryExtension/issues)；代码开源，大家也可以自己修改（构建方法见下面的[开发](#开发)）。

## 安装与升级

在 [发行页](https://github.com/Noneoi/KQPetInventoryExtension/releases/latest) 下载文件名含 **copy-ready** 的 ZIP。

1. 关闭正在运行的氪奇客户端。
2. 解压压缩包。
3. 把 **启动精灵工作台.cmd** 和 **KQPetQuickStart** 文件夹一起复制到 `KQPro*.exe` 所在目录（升级时覆盖旧文件）。
4. 以后都双击 **启动精灵工作台.cmd** 启动游戏。

```text
氪奇客户端目录/
├─ KQPro*.exe
├─ 启动精灵工作台.cmd
└─ KQPetQuickStart/
```

启动脚本会自动安装插件，但不会擅自联网检查版本。需要更新时打开 **设置 → 软件更新**，点击 **检查更新**：页面会读取本仓库最新的 GitHub 正式版并展示完整发行说明；确认后再点击 **更新到此版本**。下载内容通过全部校验后会安全暂存，关闭氪奇并再次双击 **启动精灵工作台.cmd** 即完成原子切换。断网、GitHub 不可用或校验失败都不会影响当前已验证版本，详情写入 `KQPetData\updates\auto-update.log`。草稿版、预发行版和预览包不会安装。当前版本号显示在工作台左侧栏（「插件 v3.1.0」），鼠标悬停可看到完整构建标识。

## 第一次使用

1. **更新官方数据**：打开 **设置 → 数据更新**，点击 **全部检查更新**。插件会下载并自动解包官方更新后的游戏数据（精灵字典、养成规则、兑换目录、图片索引、日常任务等）。第一次需要准备解析工具，可能要几分钟。
2. **读取精灵列表**：进入游戏后，在「精灵」页点击 **刷新背包/仓库**。
3. **读取仓库精灵详情**：在「精灵」页点击 **刷新仓库详情**。精灵多的话需要一段时间，可以随时暂停、继续或取消。
4. **调整刷新速度（建议）**：在 **设置 → 刷新参数 → 仓库详情队列** 里把「每只请求间隔」调到 **2000 毫秒（2 秒）**。默认是 1 秒，太快的话服务器可能来不及返回，精灵详情会加载不出来。
5. **只刷新部分精灵**：点击「筛选 / 刷新范围」，在「详情刷新范围」里只勾选需要的时代（灵初、神运、星迹、启元、其他），就只会刷新这些时代的精灵。

读到的精灵数据都保存在本地，下次打开直接显示，不用每次重新读取。

### 为什么仓库详情要一只一只读？

这是游戏本身的机制：背包和仓库列表只返回精灵的简要信息（名称、等级、战力等），完整的培养数据（星神、星轮、元魂、源兽、天赋……）只能对每只精灵单独请求一次。所以插件会按你设置的间隔逐只读取，读完保存到本地，之后只在你点击某只精灵或手动刷新时才更新。详细说明见 [设计与逆向依据 · 官方协议与身份](docs/设计与逆向依据.md#3-官方协议与身份) 和 [本地缓存与手动更新](docs/local-cache-and-manual-updates.md)。

## 功能

工作台左侧有四个页面（快捷键 Ctrl+1～4），加上设置和诊断。

### 精灵

- **背包与仓库列表**：普通仓库和精英仓库分开显示；可按名称、实例 ID 或拼音首字母搜索；可按属性、职业、时代筛选；可按战斗力、极限战斗力、图鉴序列、获得时间排序。
- **精灵详情**：点击精灵先显示本地保存的详情；游戏在线时再读取这一只的最新数据并保存。只显示这个时代有的养成项（例如神职看潜能和源兽装备，启元看元魂）。召唤物和神使契约关系也会列出，点击关联精灵可以直接打开它的详情。
- **技能资料**：详情区单独提供“技能资料”页，按种族 ID 只显示该精灵实际拥有的普通技、超杀技、神运/灵初天命技、英雄技、通灵技、元素/转化/赋能/幻元技等；技能说明里的机制词条会加粗，鼠标悬停时显示对应机制。资料从本地公共缓存读取，不会因为打开页签而请求游戏。
- **精灵分析**：区分官方极限战斗力、已装备战力、本地持有可达战力和至高战力；列出元魂、源兽、星轮、红星等培养缺口，按「需要 / 已有 / 还差」显示。已经在这只精灵星神背包里、但还没装上的红星也会算进去。
- **至高标记**：本地持有资源能达到至高战力时，列表名称后面显示「（至高）」。
- **放入背包 / 放入仓库**：直接移动精灵。移动前后都会重新读取列表核对，背包满时需要选一只交换。

### 商店

- 列出常驻和活动的**指定精灵兑换**，并找出你账号里能用上这个商品的精灵。
- **搜索框**：按兑换项目名、商店名或拼音首字母查找。
- **资源情况**：每个兑换项目显示「足够 / 还差多少 / 余额未读取」；鼠标悬停可看到每种资源「需要 / 拥有 / 还差」。
- **刷新兑换次数**：手动读取当前账号的剩余兑换次数、货币和活动币。

### 日常

- 日常任务、周常任务的进度和活跃度奖励领取状态。
- 当前活动列表和待处理的红点。
- 星轮探险、缤纷树、源兽之门、全民斗技、农场、竞技场等玩法的剩余次数。
- 点击「手动刷新任务/活动」读取；没有自动刷新。

### 资产

- **账号资产总览**：精灵总数、各位置数量、至高已满数量、存在培养缺口的数量、缺少详情的数量等。
- **养成诊断中心**：按「只看可提升」「缺少普通红星」「星神等级待提升」「元魂未满」「当前兑换商店可提升」等条件筛出对应精灵。
- **行动建议**：分成「现在可以处理」「还缺资源 / 条件待确认」「本地培养建议」三类。
- **统计本地红星**：统计本地详情里已装备和星神背包中的普通红星、万变红星，不联网。
- **历史快照**：记录每天的养成指标，可以比较最近两次的变化，也可以查看单只精灵的历史。
- 养成分析只在点击「重新计算养成分析（仅本地）」时计算，不发送服务器请求。

### 设置

- **本地缓存**：查看占用、打开数据目录、按账号/精灵/图片删除缓存、备份为 ZIP、从 ZIP 恢复、更换缓存目录。
- **数据更新**：「全部检查更新」，或者单独更新精灵与养成资料、兑换商店、精灵图片索引、星神与属性图标、日常与活动中的某一类；「补齐缺失图片」可以一次补全当前账号精灵的图片。
- **刷新参数**：列表请求间隔和超时、仓库详情的每只间隔、每批数量、批间休息、超时、失败重试次数，以及移动请求的超时。

界面会记住你的排序、筛选、标签页、分栏宽度、窗口大小和上次打开的页面。

## 刷新机制

插件**不会自己定时联网**，所有查询都来自你的操作：

| 操作 | 会发生什么 |
| --- | --- |
| 启动、切换页面、排序、筛选、翻页 | 只用本地已有数据，不发请求 |
| 点击一只精灵 | 先显示本地详情；游戏在线时查询这一只，成功后更新并保存 |
| 刷新背包/仓库 | 重新读取背包和仓库列表 |
| 刷新仓库详情 | 按刷新参数逐只读取所勾选时代的精灵，支持暂停、继续、取消 |
| 精灵分析 → 刷新材料背包 | 读取普通材料和空闲源兽数量 |
| 商店 → 刷新兑换次数 | 读取兑换次数、货币、活动币和价格档位 |
| 商店 → 更新兑换项目/适用精灵 | 只检查官方兑换目录有没有更新 |
| 日常 → 手动刷新任务/活动 | 读取任务进度、活跃度、红点和玩法次数 |
| 设置 → 全部检查更新 | 检查全部官方公共数据，只下载官方版本有变化的部分 |
| 设置 → 单独更新某一类 | 只检查这一类官方数据，其余保持不变 |
| 查看图片 | 本地有图直接显示；缺图时单独下载这一张并保存 |

- **断网、超时或返回无效时**，保留原来的数据和时间，不会用坏数据覆盖。
- **标注「上次读取」「待确认」「周期未确认」的数字**，是之前读到的值，可能已经跨天或跨周。这类数字不会显示成绿色，请以游戏内为准，或者手动刷新一次。
- **官方数据更新**不会读取任何账号信息；账号相关的数据（次数、材料、任务）只在你点对应的刷新按钮时读取。

## 本地数据

数据默认保存在客户端目录下的 `KQPetData`，和插件版本目录分开，升级插件不会丢失。在 **设置 → 本地缓存** 可以查看占用、打开目录、备份、恢复和迁移。

```text
KQPetData/
├─ accounts/<账号>/
│  ├─ inventory.json               背包/仓库列表
│  ├─ details/<实例ID>.json         每只精灵的最新详情
│  ├─ derived/                     可重建的分析索引
│  ├─ cultivation-materials.json   材料背包
│  └─ shops.json / routines.json / asset-analysis.json / snapshots
├─ catalog/                        官方公共数据（精灵字典、技能资料、兑换目录、图片索引、日常任务）
│  ├─ pet-skill-data.json          可手动更新的官方技能、词条及种族对应缓存
│  └─ pet-skill-supplement.json    随发行版固定的机制依据与灵初技能简评
├─ images/pets/                    精灵图片
├─ images/stargods/ images/attributes/   星神与属性图标
├─ data-tools/                     数据更新用的本地解析工具（Python、Java、JPEXS）
└─ ui-preferences.ini              界面设置（排序、筛选、窗口大小等）
```

每只精灵的详情只保留最新一份，不会越存越多；程序也不会自动清理这些文件。

## 常见问题

- **仓库详情加载不出来 / 失败很多**：在设置里把「每只请求间隔」调大到 2000 毫秒，必要时再调大「单只详情请求超时」。失败的精灵可以之后再刷新一次。
- **升级后又变回了旧版本**：没有替换 **KQPetQuickStart** 文件夹。用新包里的 **启动精灵工作台.cmd** 和 **KQPetQuickStart** 一起覆盖。
- **游戏更新后数据不对**：点 **设置 → 数据更新 → 全部检查更新**。官方数据结构有变化、暂时解析不了时，会保留旧数据并提示原因。
- **精灵图片不显示**：先做一次「全部检查更新」（会准备图片解析工具），再到设置里点「补齐缺失图片」。
- **想卸载**：关闭客户端，在客户端目录的 PowerShell 里运行 `.\KQPetQuickStart\package\tools\uninstall.ps1 -OriginalDir .`，它会移除插件入口，保留原版客户端和你的数据；之后再删除 **启动精灵工作台.cmd** 和 **KQPetQuickStart**。`KQPetData` 是你的本地数据，按需保留。

## 开发

### 构建

想自己改代码的话按下面步骤构建；改完先用预览包在测试客户端上验证。

需要 Windows x64、MSVC C++ 工具链、CMake 3.24+，以及 **Qt 6.6.3 MSVC 2019 64-bit** 开发包。构建固定使用该 Qt 版本；扩展与宿主共享 Qt ABI，运行时必须通过架构、导出符号及客户端接口检查。

```powershell
git clone https://github.com/Noneoi/KQPetInventoryExtension.git
Set-Location .\KQPetInventoryExtension

# 将 QtRoot 改为自己的 Qt 安装目录。
.\scripts\build.ps1 -QtRoot 'D:\Qt\6.6.3\msvc2019_64'
ctest --test-dir .\build-v2 -C Release --output-on-failure
```

默认构建目录是 `build-v2`，配置为 `Release`；可指定 `-BuildDirectory`、`-Configuration` 和 `-Targets`。主要产物位于 `build-v2\bin\Release`：

| 产物 | 用途 |
| --- | --- |
| `KQPetInventory.dll` | 进程内扩展 |
| `KQPetLauncher.exe` | 配对版本加载器，由稳定入口调用 |
| `KQPetBootstrap.exe` | 打包后作为客户端根目录的 `KQPetLauncher.exe` |
| `KQPetReleaseCheck.exe` | 读取构建身份、检查发行文件 |
| `KQPetCompatibilityCheck.exe` | 离线兼容检查 |
| `KQWorkbenchUiPreview.exe` | 使用模拟数据的独立工作台预览 |

客户端适配不限定氪奇 1.1.3/1.1.4，也不依赖固定文件名、整文件哈希或历史地址。启动器与 DLL 检查当前客户端接口；未识别或 ABI 不兼容时给出原因。通过检测不等于所有未来客户端都保证可用。详见 [设计与逆向依据 · 客户端版本自适配](docs/设计与逆向依据.md#21-客户端版本自适配)。

### 代码结构

源码按职责分层存放（Domain 不依赖任何上层；UI 只经只读视图与值契约访问 Application，由 `tools/build` 下的边界检查保证）：

```text
src/
├─ compatibility/  runtime/  loader/  bootstrap/   原生（无 Qt）：客户端兼容检测、启动通道、版本加载器、稳定入口、发行清单
├─ domain/            纯 QtCore 值与规则（战力、培养、商店条件、推荐），不做 I/O，没有单例
├─ contracts/         跨层共享的冻结值契约
├─ storage/           单 I/O 线程、原子写入、诊断存储
├─ diagnostics/       构建信息、诊断日志、目标 Profile 守卫
├─ protocol/          封包契约、会话、入站队列、出站传输
├─ bridge/            MinHook 内联钩子、原版客户端桥接与窗口定位
├─ application/
│  ├─ runtime/        ApplicationRuntime 装配、数据更新、缓存管理
│  ├─ catalog/        精灵详情、技能资料、商店兑换、日常活动目录及其读写
│  ├─ pet/            精灵仓库、记录/派生缓存、刷新与移动
│  ├─ shop/  routine/ 商店与日常活动控制器
│  ├─ analysis/       资产分析、推荐适配、后台分析 Worker
│  ├─ views/          供 GUI 读取的只读视图、投影与发布器
│  ├─ images/         图片调度、解码与落盘
│  └─ common/         控制器共用的缓存写入、观察时效与只读请求跟踪
├─ ui/                workbench/ pet/ detail/ shop/ routine/ analysis/ common/
└─ extension/         KQPetInventory.dll 入口与装配根（dllmain、ExtensionContext、嵌入资源）
```

include 统一写成相对 `src/` 的完整路径；CMake 按层拆在 `cmake/`；测试按同样的层放在 `tests/` 子目录。依赖边界、构建与测试布局、以及怎样验证整理不改变功能，见 [架构与代码组织](docs/architecture.md)。

### 开发打包与高级部署

预览包使用同一构建的加载器、DLL 和测试报告，避免混用旧产物。以下发行脚本使用 `build.ps1` 中的默认 Qt 路径，按本机环境配置后运行：

```powershell
$reportDir = Join-Path (Get-Location) ('build-v2\validation\preview-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
.\scripts\test-release.ps1 -BuildDirectory .\build-v2 -ReportDirectory $reportDir
.\scripts\package-release.ps1 -TestReport (Join-Path $reportDir 'test-report.json') -Preview
```

报告绑定具体源码和产物。`test-release.ps1` 运行完整注册测试；平时也可针对改动运行相关测试。正式包额外要求对应的 `-AcceptanceReport`，定向测试记录不能代替真实客户端验收。

#### 生成复制即用包

将已验证标准包的解压目录传给包装脚本：

```powershell
.\scripts\package-copy-ready.ps1 -PackageDirectory '.\dist\已验证标准包目录'
```

复制即用包增加自动部署入口，沿用标准包中已验证的应用二进制、manifest 和测试报告，不重新编译或改变应用版本。

#### 发布可由软件内更新的 GitHub Release

软件内更新只读取 `Noneoi/KQPetInventoryExtension` 的最新正式 Release。发布时需要：

1. Release 标签使用包内版本号，例如 `v3.1.0`；不要勾选 Draft 或 Pre-release。
2. 上传 `package-copy-ready.ps1` 生成的 `KQPetInventory-<releaseId>-win-x64-copy-ready.zip`。
3. 同时上传脚本生成的同名 `.zip.sha256` 文件；不要修改两个文件的名称或内容。

更新器要求一个 Release 中恰好有一组符合命名规则的 copy-ready ZIP 和校验文件。下载后还会检查附件大小、SHA-256、ZIP 路径、包清单、测试报告、二进制构建身份、Release 标签与版本号，并拒绝降级。联网检查只会在用户点击“检查更新”时发生。

#### 高级：手动部署标准包

需要手动指定目录时，关闭测试客户端后执行：

```powershell
$client = 'C:\Games\KQPro-test'
$package = 'C:\Downloads\实际预览包目录'
& "$package\tools\deploy.ps1" -OriginalDir $client -PackageDirectory $package -AllowPreview
& "$client\KQPetLauncher.exe"
```

启动客户端根目录的稳定入口，不直接运行构建目录中的版本加载器。配对版本位于 `KQPetRuntime\releases\<releaseId>`；运行中的客户端收到更新时只暂存，关闭后重新部署完成激活。发行包不包含原版客户端或个人数据。

关闭客户端后，可用同一包内的 `rollback.ps1 -OriginalDir $client` 回退，或用 `uninstall.ps1 -OriginalDir $client` 卸载扩展入口。个人数据与原版客户端保留。
