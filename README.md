# 氪奇精灵工作台

给奥奇传说玩家用的养成辅助工具：在 **氪奇 Pro 官方客户端** 里加一个「精灵工作台」窗口，把背包和仓库里的精灵、培养缺口、兑换商店、日常任务和账号资产集中到一处查看，帮你判断下一步该练谁、该换什么。

插件通过外置启动器和进程内扩展工作，**不修改原版客户端 EXE**，卸载后客户端恢复原样。

当前共享资料架构（2026-10-14）：整个工作台和战斗回放使用同一个公共数据集，以 `KQPetData/public/current.json` 选择完整版本；设置统一检查、应用及恢复资料，精灵、技能、Buff、养成和商店共用资料详情。实现与验收入口见 [第二轮实施记录](docs/共享资料第二轮实施记录.md) 和 [第三轮实施记录](docs/共享资料第三轮实施记录.md)；下文带日期的验收记录保留当时事实，不代表当前目录布局或安装状态。

## 支持范围

- **目前只支持氪奇 Pro 官方客户端**（已在 V1.1.4 上验证）。其他客户端以后再做——不过用的人应该也不多。
- **脱机版**暂时不做：做起来问题比较多，后面打算用 Astra 和 Fable 再试试。
- 有问题直接提 [Issue](https://github.com/Noneoi/KQPetInventoryExtension/issues)；代码开源，大家也可以自己修改（构建方法见下面的[开发](#开发)）。

氪奇更新后如找不到主程序，启动时会弹出 EXE 选择窗口；也可双击包内 **选择氪奇主程序.cmd** 更换，选择的完整路径会自动记住。

## 安装与升级

在 [发行页](https://github.com/Noneoi/KQPetInventoryExtension/releases/latest) 下载文件名含 **copy-ready** 的 ZIP。

1. 关闭正在运行的氪奇客户端。
2. 解压压缩包。
3. 把 **启动精灵工作台.cmd**、**选择氪奇主程序.cmd** 和 **KQPetQuickStart** 文件夹一起复制到 `KQPro*.exe` 所在目录（升级时覆盖旧文件）。
4. 以后都双击 **启动精灵工作台.cmd** 启动游戏。

```text
氪奇客户端目录/
├─ KQPro*.exe
├─ 启动精灵工作台.cmd
├─ 选择氪奇主程序.cmd
└─ KQPetQuickStart/
```

启动脚本会自动安装插件，但不会擅自联网检查版本。需要更新时打开 **设置 → 软件更新**，点击 **检查更新**：页面会读取本仓库最新的 GitHub 正式版并展示完整发行说明；确认后再点击 **更新到此版本**。下载内容通过全部校验后会安全暂存，关闭氪奇并再次双击 **启动精灵工作台.cmd** 即完成原子切换。断网、GitHub 不可用或校验失败都不会影响当前已验证版本，详情写入 `KQPetData\updates\auto-update.log`。草稿版、预发行版和预览包不会安装。当前版本号显示在工作台左侧栏（「插件 v4.0.0」），鼠标悬停可看到完整构建标识。

## 第一次使用

1. **更新官方数据**：打开 **设置 → 数据更新**，点击 **检查并更新**。插件会下载并自动解包官方更新后的游戏数据（精灵字典、养成规则、兑换目录、图片索引、日常任务等）。第一次需要准备解析工具，可能要几分钟。
2. **读取精灵列表**：进入游戏后，在「精灵」页点击 **刷新背包/仓库**。
3. **读取仓库精灵详情**：在「精灵」页点击 **刷新仓库详情**。精灵多的话需要一段时间，可以随时暂停、继续或取消。
4. **调整刷新速度（建议）**：在 **设置 → 刷新参数 → 仓库详情队列** 里把「每只请求间隔」调到 **2000 毫秒（2 秒）**。默认是 1 秒，太快的话服务器可能来不及返回，精灵详情会加载不出来。
5. **只刷新部分精灵**：点击「筛选 / 刷新范围」，在「详情刷新范围」里只勾选需要的时代（灵初、神运、星迹、启元、其他），就只会刷新这些时代的精灵。

读到的精灵数据都保存在本地，下次打开直接显示，不用每次重新读取。

### 为什么仓库详情要一只一只读？

这是游戏本身的机制：背包和仓库列表只返回精灵的简要信息（名称、等级、战力等），完整的培养数据（星神、星轮、元魂、源兽、天赋……）只能对每只精灵单独请求一次。所以插件会按你设置的间隔逐只读取，读完保存到本地，之后只在你点击某只精灵或手动刷新时才更新。详细说明见 [设计与逆向依据 · 官方协议与身份](docs/设计与逆向依据.md#3-官方协议与身份) 和 [本地缓存与手动更新](docs/local-cache-and-manual-updates.md)。

## 功能

工作台左侧有五个页面（快捷键 Ctrl+1～5），加上设置和诊断。

公共资料以 `KQPetData/public/current.json` 为唯一当前入口，完整清单位于 `public/releases/<清单散列>/manifest.json`，七类资料及附件按内容散列存入 `public/objects/<内容散列>/data`。首次迁移复用原 `catalog/` 和实际内置基线，保留旧文件；已有公共版本后不再逐类从旧目录拼接现用资料。回放完整资料仍按需在后台加载，资料未就绪不以空库解析。回放页的“重新读取资料”只读本地；当前战报固定打开时的资料，明确点击“使用更新后的资料”才从原战报重新解释，并恢复到可确定的行动位置，失败保留原场景。

设置 → 数据更新以“检查并更新”为主要入口，分类入口收进“高级更新”。更新器在独立事务中准备完整候选，原生发布器核验全部对象、依赖及报告后一次切换当前指针，再由 Core 一次发布完整快照；候选通过、磁盘提交和当前会话应用分别记录。精灵、技能、商店、回放、图片和图标按已登记依赖一起检查，核心失败时整组保旧；图片失败可保留原图片对象，不阻止已通过的核心资料应用，日常资料独立处理。界面提供“重试未完成项”“查看变化”“结果详情”“恢复上一份资料”和“导出诊断”，只读公共官方资源，不依赖登录、不发送游戏操作。

更新输入从一开始取工作台与回放的完整资源并集：目前固定声明包含 81 个 Flash SWF、2 个属性 FUI、17 个 H5 文件及 1 个额外版本依赖；官方活动链接、面板、星神和精灵图标引用继续追加。各读取视图使用同一条 Flash `start.v → versiondata → start.u.f` 和 H5 `version → start.files → .mix` 规则，同版本资源在一次更新中只下载一份，完全相同的 AS 解析请求也复用结果。各视图保留自身字段和结构，不以精简表覆盖完整表。工作台精灵增量按官方严格较新时间戳应用；源兽、传说石、潜能三张旧表现已纳入更新。技能更新按全部来源字节及解析器指纹检查变化，不再仅凭入口版本号跳过。`public/transactions/<事务>/diagnostics/public-resource-manifest.json` 保存初始清单、各资源使用方、动态下载、版本、SHA 和各类别结果；历史引用与本次下载分开标记。

目前允许已支持的战斗配置 XML、技能文字字面表及精灵字典数据变化；解析代码、其它受固定依据约束的资源或未知结构变化会提示需适配并保留旧资料，不能保证任意未来版本自动兼容。星神/元魂/星轮的 Flash/H5 对照在更新中重做；气运、溯灵和旧传说规则中的历史 H5 比较保留原依据，不冒充重新抓取。整套公共资料恢复已实现，恢复前仍做原生完整试读，账号数据和个人商店选择不随资料版本回退；内容相同的对象跨版本复用，完整回放包与精简字典尚未做字段级去重或按需分片。开发验收使用隔离目录，程序覆盖仍走完整版本安装流程，保留旧版本及账号数据。

所选固定依赖在解析前统一下载并核对 SHA；即使版本号相同，文件内容变化也会使相应缓存失效。Flash 引导加载器与模块加载器若引用不同版本，两份依据都保留且按消费者分别核验。技能更新校验原有 21 张完整输入、全部输出表及精灵关联，明显缩减时拒绝相应候选。精灵、技能与回放还会逐项检查编号、字段、原名及明确引用；回放另审计原始表和字段的消费覆盖。官方空说明和有原文证据的定义缺项保留，不猜造补齐。本次质量报告保存在 `public/transactions/<事务>/quality/`，同目录的 `validation.json`、`changes.json` 和 `receipt.json` 分别记录整版检查、变化及提交/应用结果。详细协议见 [公共数据更新](docs/manual-public-data-updater.md)。

精灵详情中的名称、技能与已关联养成条目，商店的“项目资料”，以及回放中的官方资料链接进入同一个可返回、前进的资料窗口。普通正文显示官方名称、说明和已有适用条件，来源折叠，技术编号与原始记录进一步展开；只连接已证实关系，不凭名称或同号跨表关联。详情沿用入口正在展示的快照，旧回放仍使用本场资料，查看关联不重置回放进度。

本地读取不依赖游戏抓包通道，也不触发游戏请求；其他游戏操作仍保留原有会话校验。完整外部库须符合当前 format 3、核心字段与来源记录契约，记录数须与生成摘要一致。压缩包逐字节保留原 JSON 和证据字段，解压时核对长度与 SHA-256，拒绝损坏、截断、多流、额外尾部及超限内容；每步最多读取和解压各 64 KiB，包文件上限 32 MiB、原文上限 128 MiB。完整性校验不会把缺少证据的机制变为已确认，也不为任意本地文件提供官方真实性认证。当前仍在后台整份解析资料；压缩减少磁盘和分发体积，不代表运行时内存同比减少。

构建 `KQPetInventory` 或独立目标 `KQBattleReplayCatalogPack` 会生成 `build-v2/data-packs/battle-replay-catalog.brpack`（实际目录随构建目录变化），使用 Qt 现有 zlib，无新增运行时 DLL。原有内置资料已经由 Qt 压缩，继续作为后备，不再嵌入一份新包。设置更新需要的基线由已有内置资料分段压缩生成，不把 94 MB 原始 JSON 再复制进工具目录。包格式、更新支持边界及复现命令见 `tools/battle_replay/README.txt`。

“战斗回放”可导入本地 `brush` 日志，在敌我双九宫格按官方技能前、出手、反击、技能后阶段连续播放，同组目标同步更新，阶段动画完成后衔接下一段；暂停、倍速和逐条作用核对均可用。生命用红条、气势用橙条显示当前值/参考值，护盾显示蓝色余额；双方通灵条按各自日志满值分格。每格展示单位当前 Buff，召唤绿框、证据充分的元能目标粉框，幻元单独核对。点击作用列表会定位对应小步，突出来源、目标、前后数值并连接有证据的关系；施加者未记录时明确标注。支持选择玩家阵容、按单位筛选、只看关键变化及跳转事件。解析和显示依据官方包，原始字段始终可查；不补造动画帧序、历史版本机制或日志未给出的因果。开发者可运行 `scripts/start-battle-replay.ps1` 打开独立预览，数据来源与复现步骤见 `tools/battle_replay/README.txt`。

播放进度按大回合分段，上方明确区分各回合，顶部只显示“第几回合 · 第几小回合”；小回合按当前大回合内的完整行动从 1 编号，开局、战斗段、结束和技能内部小步骤不另计，全场完整行动编号保留在悬停提示中供核对。大回合按行动日志 `csn` 的连续段划分，缺失显示未记录，不从前一个回合补猜；同一回合号在其他回合后再次出现仍是独立段。

“回合总览”在当前大回合内分敌我展示死亡与复活；“按精灵”只展开同类生命事件，每个已登记的完整精灵身份独立一行，没有死亡复活记录的精灵也保留，按双方查看并可滚动。精灵使用首次记录的原名，不按同名、种族或格子合并；视图切换不改变当前位置，也不打断播放。悬停标记查看精灵原名与对应小回合，点击回到该完整行动开始并暂停，重叠事件可展开选择。切换我方视角同步调整两侧和精灵行；“动作细节”仍保留原来的回合跳转，事件导航仍能定位实际发生的小步骤。死亡/复活仅依据已记录的生命归零与从零恢复；登场、召唤和显现不当作复活，登场状态未确认时只注明生命变化，不补造触发技能或原因。

生命、护盾、气势的非零变化以红、蓝、橙大字向右上方倾斜约 15° 显示，允许伸出格子。每只精灵的每条数值保留最近一次变化，直到该指标下一次变化、切换行动来源或行动结束；连续扣血、先扣后加分别显示，不累计合计。虚色只标出当前这一段的改变范围：增加用浅色加号边框，减少用斜纹，下段开始时收尾；条内始终显示本段已记录余额。点击条子仍可查看本次行动至今的全部原始记录。对官方明确按列表依次应用的同字段数值，使用已记录前后值细分阅读段；原有命令与气势/Buff屏障保持，多目标并行，目标攻击合计不拆成假想命中，未知顺序、混合状态重设和不同回调路径不拆。普通数值段在 1 倍速下至少展示 0.6 秒，生命归零及恢复保留更长读数时间；这属于阅读节奏，不声称原版帧时刻。九宫格上方的“数字”选项可切换完整数字与亿 / 万分段（如 123456789 → 1亿2345万6789），同时作用于浮字和三种条内余额，保留完整精度、增减号与未知标记；工作台记住选择，切换不打断播放。暴击小标识只跟随当前对应的直接伤害，强效及弱效写在对应箭身内。

战场内另显示双方行动队列、轮次、队伍 Buff 和英雄技能；实际组合技、反击普攻、队伍技能分别按官方分支解析。单纯队伍触发不补画攻击，生命/护盾与后续气势/Buff 保留回调边界。通灵以及生命重设的原始差值单独保留，格内显示满气势、当前属性和技能替换。开战道具结果、联盟兵工厂不在本轮范围内。

格内 Buff 集合默认收起，只自动显示已经播到的本回合新增、移除和明确触发；“展开 / 收起”在原格内查看完整列表，展开时暂停播放。重复成员只合并相同 Buff 和相同已记录来源，数量表示记录条数。顶部进度贯穿整次行动，普通变化紧凑衔接，生命归零、恢复、登场和变身保留更长的阅读时间；数值和官方结算顺序保持不变。

Buff 分为有官方说明的登记、未解释记录、播放详情三个独立展开入口。已撤销旧的 2014 项“纯动画”名单：说明来自官方 mess 或客户端实际消费的 beffect 词表，名称、素材编号、隐藏及只播一次均不判断状态性质。未解释登记折叠保留编号、名称、来源与逐条跳转；同一编号的实际数值触发、执行行为和显示指令仍独立展示。播放详情只解释等待、帧回调、隐藏、一次播放等规则，不吞掉成员或效果。重复数是记录数，动画编号不是层数。等待 Buff 的 summonAppear 仅显示“恢复显示”，不再修改登场标志或产生登场事件，也不据此推断召唤成功或复活。核查证据位于 `build-battle-reference/buff-semantic-audit-20261013/`，旧名单留存于 `build-v2/validation/buff-roles-20261013/superseded-playback-whitelist.h`，仅作历史审计材料。

面向用户的卡片、施法标题、通灵条和普通详情只展示名称、实际数值与可读效果，不附带内部编号、字段名、路径或动画帧参数。精灵、技能、Buff、阵容详情均可显式打开“原始详情”，原始编号、完整配置、来源路径、逐条历史及内部跳转身份保持完整；未核实名称仍明确待确认，不借外观名或猜测补齐。播放、阵营和状态使用一致的圆角浅色视觉；技术查询收纳到“资料与原文”，生命红、护盾蓝、气势橙及召唤/元能边框保持。此次只改变呈现，不改变 Buff 分类、层数解释、动作顺序与已记录余额。

九宫格效果提示覆盖已核实的异常状态、Buff 移除与触发、具体技能替换、形态和属性前后变化、开局元能及自身幻元、数值伤害来源、印记等特殊 Buff、神职攻防与天启、达到满气势、通灵充能/扣除/生效，以及具体小神龙或队伍效果来源。多个关键效果同时保留紧凑标记，展开 Buff 后仍能看见结果；施加方独立标为我方、敌方或来源未记。开局来源关系是官方配置与初始记录的唯一匹配说明，不冒充战斗中施法。

箭头按施法者与目标的实际队伍区分：对手红色，队友和自身绿色，队伍未知保持灰色；强效、弱效和明确神属性强效标在对应箭头旁。格内以图标、颜色和共享进度动画突出闪避、免疫、格挡、暴击、行动受限、生命归零/恢复、登场、变身等已记录事件，也显示官方配置明确的 Buff 状态与属性升降；“暴击↑”与本次被暴击分别处理。多个效果可点击切换，同格精灵各自保留图标，展开 Buff 时让出完整列表。追击本体和变身来源保留独立关联，小神龙按明确出手记录显示阶段；隐藏飘字规则不删减数值或成员。本轮不扩展组队、战后奖励、剧情与嵌入事件。

同格单位各有独立名称条、状态和关系端点；阶段内“归零后恢复”按已记录顺序显示，数值标签来自官方白名单。未知数值可点击条内 `?`，未关联实例在画布内查看原文，不生成虚假精灵。行动队列可展开完整顺序、变化与本轮已出手记录，阵容资料和所用官方配置版本也可在画布内查看。

正式工作台复用客户端已有的被动入站通道，并只读监听授权目录 `C:\keqi\config64\brush`。完整新战报经过稳定性检查与 SHA-256 去重后进入待阅列表，点击才打开，不打断正在播放的内容。自动选择我方需要本会话已接纳的账号与官方登录昵称相符，且昵称在本场唯一匹配；无法确认时保留手动视角。独立预览仍可离线打开文件，不要求登录。

### 精灵

- **背包与仓库列表**：普通仓库和精英仓库分开显示；可按名称、实例 ID 或拼音首字母搜索；可按属性、职业、时代筛选；可按战斗力、极限战斗力、图鉴序列、获得时间排序。
- **精灵详情**：点击精灵先显示本地保存的详情；游戏在线时再读取这一只的最新数据并保存。只显示这个时代有的养成项（例如神职看潜能和源兽装备，启元看元魂）。召唤物和神使契约关系也会列出，点击关联精灵可以直接打开它的详情。
- **技能资料**：详情区单独提供“技能资料”页，按种族 ID 只显示该精灵实际拥有的普通技、超杀技、神运/灵初天命技、英雄技、通灵技、元素/转化/赋能/幻元技等；技能说明里的机制词条会加粗，鼠标悬停时显示对应机制。资料从本地公共缓存读取，不会因为打开页签而请求游戏。
- **精灵分析**：区分官方极限战斗力、已装备战力、本地持有可达战力和至高战力；列出元魂、源兽、星轮、红星等培养缺口，按「需要 / 已有 / 还差」显示。已经在这只精灵星神背包里、但还没装上的红星也会算进去。
- **至高标记**：本地持有资源能达到至高战力时，列表名称后面显示「（至高）」。
- **放入背包 / 放入仓库**：直接移动精灵。移动前后都会重新读取列表核对，背包满时需要选一只交换。

### 商店

- 列出常驻和活动的**指定精灵兑换**，并找出你账号里能用上这个商品的精灵。
- **搜索框**：按兑换项目名、商店名或拼音首字母查找。
- **资源情况**：每个兑换项目显示「足够 / 还差多少 / 余额未读取」；鼠标悬停可看到每种资源「需要 / 拥有 / 还差」。
- **刷新兑换次数**：手动读取当前账号的剩余兑换次数、货币和活动币。
- **自动添加 + 手动补充**：识别到的指定精灵培养兑换默认勾选，可以按商店或单项取消，保存后更新、重启都保留取消结果。在 **设置 → 数据更新 → 手动补充商店 / 兑换项目** 中，只列出指定精灵提升，包括符合条件的兑换、签到、进度领取，以及明确的指定养成与材料二选一；支持搜索、批量勾选和取消。窗口同时显示费用、领取门槛、静态次数限制和北京时间有效期。精灵自选、材料任选、自选礼包、普通固定材料和宣传入口均不显示，旧缓存中已选中的自选项目也会排除。新发现的默认项目自动勾选，新发现的手动项目仍需选择。
- **新活动识别**：按官方奖励字段和公共养成配置解析，活动改名或沿用相同结构时无需单独适配。支持进度奖励、抽奖中的指定养成及公共养成入口；仅写“通用养成”等笼统名称时补充实际效果，极品套餐列出组成。未完整识别的活动可在手动补充窗口查看具体原因，全新结构仍需适配。

- 日常任务、周常任务的进度和活跃度奖励领取状态。
- 当前活动列表和待处理的红点。
- 星轮探险、缤纷树、源兽之门、全民斗技、农场、竞技场等玩法的剩余次数。

### 资产

- **账号资产总览**：精灵总数、各位置数量、至高已满数量、存在培养缺口的数量、缺少详情的数量等。
- **分类筛选与汇总**：可组合神源兽、星轮、元魂、红星类别，灵初／神运时代，以及 SP、SSS、SS、S、A 原名评级；皮肤按官方对应的原型精灵评级，皮肤品阶不参与。统计当前筛选精灵的材料缺口，区分材料种类和信息不足。源兽、精华、元魂显示剩余培养消耗总量（未扣账号库存）；红星按每只精灵实际持有情况计算。

- **本地缓存**：查看占用、打开数据目录、按账号/精灵/图片删除缓存、备份为 ZIP、从 ZIP 恢复、更换缓存目录。

## 刷新机制

插件**不会自己定时联网**，所有查询都来自你的操作：

| 操作 | 会发生什么 |
| --- | --- |
| 启动、切换页面、排序、筛选、翻页 | 只用本地已有数据，不发请求 |
| 点击一只精灵 | 先显示本地详情；游戏在线时查询这一只，成功后更新并保存 |
| 刷新背包/仓库 | 重新读取背包和仓库列表 |
| 刷新仓库详情 | 按刷新参数逐只读取所勾选时代的精灵，支持暂停、继续、取消 |
| 精灵分析 → 刷新材料背包 | 读取普通材料和空闲源兽数量 |
| 商店 → 刷新兑换次数 | 读取兑换次数、货币、活动币和价格档位 |
| 商店 → 更新兑换项目/适用精灵 | 只检查官方兑换目录有没有更新 |
| 日常 → 手动刷新任务/活动 | 读取任务进度、活跃度、红点和玩法次数 |
| 设置 → 检查并更新 | 检查全部官方公共数据，只下载官方版本有变化的部分 |
| 设置 → 单独更新某一类 | 只检查这一类官方数据，其余保持不变 |
| 查看图片 | 本地有图直接显示；缺图时单独下载这一张并保存 |

- **断网、超时或返回无效时**，保留原来的数据和时间，不会用坏数据覆盖。
- **标注「上次读取」「待确认」「周期未确认」的数字**，是之前读到的值，可能已经跨天或跨周。这类数字不会显示成绿色，请以游戏内为准，或者手动刷新一次。
- **官方数据更新**不会读取任何账号信息；账号相关的数据（次数、材料、任务）只在你点对应的刷新按钮时读取。

│  ├─ releases/<散列>/manifest.json   完整版本清单
│  ├─ objects/<散列>/data          按内容复用的不可变资料及附件
│  └─ transactions/<事务>/         候选、检查报告、变化、资源清单和收据

## 常见问题

- **仓库详情加载不出来 / 失败很多**：在设置里把「每只请求间隔」调大到 2000 毫秒，必要时再调大「单只详情请求超时」。失败的精灵可以之后再刷新一次。
- **升级后又变回了旧版本**：没有替换 **KQPetQuickStart** 文件夹。用新包里的 **启动精灵工作台.cmd** 和 **KQPetQuickStart** 一起覆盖。
- **游戏更新后数据不对**：点 **设置 → 数据更新 → 检查并更新**。官方数据结构有变化、暂时解析不了时，会保留旧数据并提示原因。
- **精灵图片不显示**：先做一次「检查并更新」（会准备图片解析工具），再到设置里点「补齐缺失图片」。
- **想卸载**：关闭客户端，在客户端目录的 PowerShell 里运行 `.\KQPetQuickStart\package\tools\uninstall.ps1 -OriginalDir .`，它会移除插件入口，保留原版客户端和你的数据；之后再删除 **启动精灵工作台.cmd** 和 **KQPetQuickStart**。`KQPetData` 是你的本地数据，按需保留。

## 开发

### 构建

想自己改代码的话按下面步骤构建；改完先用预览包在测试客户端上验证。

需要 Windows x64、MSVC C++ 工具链、CMake 3.24+，以及 **Qt 6.6.3 MSVC 2019 64-bit** 开发包。构建固定使用该 Qt 版本；扩展与宿主共享 Qt ABI，运行时必须通过架构、导出符号及客户端接口检查。

```powershell
git clone https://github.com/Noneoi/KQPetInventoryExtension.git
Set-Location .\KQPetInventoryExtension

# 将 QtRoot 改为自己的 Qt 安装目录。
.\scripts\build.ps1 -QtRoot 'D:\Qt\6.6.3\msvc2019_64'
ctest --test-dir .\build-v2 -C Release --output-on-failure
```

默认构建目录是 `build-v2`，配置为 `Release`；可指定 `-BuildDirectory`、`-Configuration` 和 `-Targets`。主要产物位于 `build-v2\bin\Release`：

| 产物 | 用途 |
| --- | --- |
| `KQPetInventory.dll` | 进程内扩展 |
| `KQPetLauncher.exe` | 配对版本加载器，由稳定入口调用 |
| `KQPetBootstrap.exe` | 打包后作为客户端根目录的 `KQPetLauncher.exe` |
| `KQPetReleaseCheck.exe` | 读取构建身份、检查发行文件 |
| `KQPetCompatibilityCheck.exe` | 离线兼容检查 |
| `KQWorkbenchUiPreview.exe` | 使用模拟数据的独立工作台预览 |

客户端适配不限定氪奇 1.1.3/1.1.4，也不依赖固定文件名、整文件哈希或历史地址。启动器与 DLL 检查当前客户端接口；未识别或 ABI 不兼容时给出原因。通过检测不等于所有未来客户端都保证可用。详见 [设计与逆向依据 · 客户端版本自适配](docs/设计与逆向依据.md#21-客户端版本自适配)。

### 代码结构

源码按职责分层存放（Domain 不依赖任何上层；UI 只经只读视图与值契约访问 Application，由 `tools/build` 下的边界检查保证）：

```text
src/
├─ compatibility/  runtime/  loader/  bootstrap/   原生（无 Qt）：客户端兼容检测、启动通道、版本加载器、稳定入口、发行清单
├─ domain/            纯 QtCore 值与规则（战力、培养、商店条件、推荐），不做 I/O，没有单例
├─ contracts/         跨层共享的冻结值契约
├─ storage/           单 I/O 线程、原子写入、诊断存储
├─ diagnostics/       构建信息、诊断日志、目标 Profile 守卫
├─ protocol/          封包契约、会话、入站队列、出站传输
├─ bridge/            MinHook 内联钩子、原版客户端桥接与窗口定位
├─ application/
│  ├─ runtime/        ApplicationRuntime 装配、数据更新、缓存管理
│  ├─ catalog/        精灵详情、技能资料、商店兑换、日常活动目录及其读写
│  ├─ pet/            精灵仓库、记录/派生缓存、刷新与移动
│  ├─ shop/  routine/ 商店与日常活动控制器
│  ├─ analysis/       资产分析、推荐适配、后台分析 Worker
│  ├─ views/          供 GUI 读取的只读视图、投影与发布器
│  ├─ images/         图片调度、解码与落盘
│  └─ common/         控制器共用的缓存写入、观察时效与只读请求跟踪
├─ ui/                workbench/ pet/ detail/ shop/ routine/ analysis/ common/
└─ extension/         KQPetInventory.dll 入口与装配根（dllmain、ExtensionContext、嵌入资源）
```

include 统一写成相对 `src/` 的完整路径；CMake 按层拆在 `cmake/`；测试按同样的层放在 `tests/` 子目录。依赖边界、构建与测试布局、以及怎样验证整理不改变功能，见 [架构与代码组织](docs/architecture.md)。

### 开发打包与高级部署

预览包使用同一构建的加载器、DLL 和测试报告，避免混用旧产物。以下发行脚本使用 `build.ps1` 中的默认 Qt 路径，按本机环境配置后运行：

```powershell
$reportDir = Join-Path (Get-Location) ('build-v2\validation\preview-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
.\scripts\test-release.ps1 -BuildDirectory .\build-v2 -ReportDirectory $reportDir
.\scripts\package-release.ps1 -TestReport (Join-Path $reportDir 'test-report.json') -Preview
```

报告绑定具体源码和产物。`test-release.ps1` 运行完整注册测试；平时也可针对改动运行相关测试。正式包额外要求对应的 `-AcceptanceReport`，定向测试记录不能代替真实客户端验收。

#### 生成复制即用包

将已验证标准包的解压目录传给包装脚本：

```powershell
.\scripts\package-copy-ready.ps1 -PackageDirectory '.\dist\已验证标准包目录'
```

复制即用包增加自动部署入口，沿用标准包中已验证的应用二进制、manifest 和测试报告，不重新编译或改变应用版本。

#### 发布可由软件内更新的 GitHub Release

软件内更新只读取 `Noneoi/KQPetInventoryExtension` 的最新正式 Release。发布时需要：

1. Release 标签使用包内版本号，例如 `v4.0.0`；不要勾选 Draft 或 Pre-release。
2. 上传 `package-copy-ready.ps1` 生成的 `KQPetInventory-<releaseId>-win-x64-copy-ready.zip`。
3. 同时上传脚本生成的同名 `.zip.sha256` 文件；不要修改两个文件的名称或内容。

更新器要求一个 Release 中恰好有一组符合命名规则的 copy-ready ZIP 和校验文件。下载后还会检查附件大小、SHA-256、ZIP 路径、包清单、测试报告、二进制构建身份、Release 标签与版本号，并拒绝降级。联网检查只会在用户点击“检查更新”时发生。

#### 高级：手动部署标准包

需要手动指定目录时，关闭测试客户端后执行：

```powershell
$client = 'C:\Games\KQPro-test'
$package = 'C:\Downloads\实际预览包目录'
& "$package\tools\deploy.ps1" -OriginalDir $client -PackageDirectory $package -AllowPreview
& "$client\KQPetLauncher.exe"
```

启动客户端根目录的稳定入口，不直接运行构建目录中的版本加载器。配对版本位于 `KQPetRuntime\releases\<releaseId>`；运行中的客户端收到更新时只暂存，关闭后重新部署完成激活。发行包不包含原版客户端或个人数据。

关闭客户端后，可用同一包内的 `rollback.ps1 -OriginalDir $client` 回退，或用 `uninstall.ps1 -OriginalDir $client` 卸载扩展入口。个人数据与原版客户端保留。
